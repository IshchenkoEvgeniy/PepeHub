# Доработка синхронизации после аудита, 16 октября 2026

Обновление 17 октября: аккаунты исключены по решению пользователя. Прямая синхронизация не требует сервера регистрации; облачное хранение по-прежнему не подключено.

Согласованный порядок: изоляция старого облачного транспорта → адреса → выборочная загрузка и Obsidian → фон Android → интернет/ретранслятор. Прямой режим сохраняется самостоятельным; инфраструктура не разворачивается автоматически.

## Уже проверенные изменения

`cloud_transport_isolation_test.dart`: локальные правки без очереди, точное сохранение старых конфликтов, независимые ревизии, поздняя квитанция и конкурентная серверная страница. Старые cloud-тесты теперь явно включают этот транспорт.

`peer_discovery_test.dart`: поддельное объявление/чужой получатель, реальный UDP, восстановление адреса через аутентифицированный TCP без смены ключа, неподходящий сервер и отзыв сопряжения. Обнаружение использует UDP 42590 и multicast 239.255.42.89; Wi-Fi Android получает multicast lock только на время включённого поиска.

Новый облачный аккаунт/хранилище этим срезом не создаётся. Таблица `legacy_cloud_outbox` хранит старую очередь отдельно, `remote_records.revision` — серверную ревизию, `cloud_local_state` — состояние, известное облачному транспорту. `records.revision` остаётся локальной ревизией. Включение старого cloud-протокола требует явного `setCloudTracking(true)`; современная синхронизация папок от него не зависит.

## Как пользоваться

1. Пересобрать и обновить оба приложения. Включить прямую синхронизацию; существующее сопряжение сохраняется. В одной Wi-Fi-сети объявления раз в 30 секунд находят новый адрес. Ключ проверяется по TCP перед сохранением адреса. При блокировке multicast/UDP можно воспользоваться «Изменить адрес» без нового сопряжения.
2. В карточке общей папки открыть **«Выбрать файлы»**: только данные / выбранные файлы / вся папка. Настройка локальная, задаётся независимо на ПК и телефоне. Новая папка через интерфейс начинает с режима без скачивания. Старые папки сохраняют прежний режим. Выключение скачивания сохраняет уже имеющиеся файлы; удаление приходит на подтверждение, когда файл входит в выбранную загрузку.
3. Для прогресса, заметок, Anki и статистики включить **«Данные приложения» на обеих сторонах**. Этот доступ независим от скачивания медиа. Связь с конкретной книгой/уроком требует проверенного источника; недостающая привязка остаётся ожидающей.
4. На Android включить **«Фоновый обмен данными приложения»**; по умолчанию только сеть без тарификации. JobScheduler запрашивается с периодом 15 минут, но Android выбирает фактическое время. Задание ограничено примерно двумя минутами и не сканирует/передаёт медиа. Новые источники проверяются при открытии интерфейса, уже связанные позиции и самостоятельные данные обмениваются в фоне. После Force stop нужно снова открыть приложение.
5. Для курса/больших файлов нажать **«Передать файлы с уведомлением»**, пока приложение открыто. На Android 13+ запрашивается разрешение уведомлений. Передачу можно свернуть и остановить из уведомления; докачка остаётся в выбранной папке. Это разовая передача, а не бесконечный фоновый демон. Android 15+ ограничивает суммарную работу `dataSync` в фоне шестью часами в сутки; обработчик таймаута останавливает передачу. Состояние последнего системного задания сохраняется отдельно и подхватывается журналом при открытии интерфейса, в том числе при ошибке до открытия БД.
6. Для разных сетей настроить одинаковый WSS-сервер и ключ в **«Обмен через интернет»** на обоих уже сопряжённых устройствах. Прямой TCP пробуется первым, после сетевой ошибки используется ретранслятор; прямой путь проверяется снова через минуту. [Запуск сервера](PEER_RELAY.md).

## Obsidian

Обновить исходники Habit Timer через `scripts/install-obsidian-library-bridge.ps1`, собрать плагин и применить новую миграцию `0014_pepehub_library_changes.sql` в Companion перед публикацией обновлённого worker. Скрипт установки добавляет эту миграцию из `004_pepehub_library_changes.sql`. В этом сеансе пользовательское хранилище/плагин и удалённый worker не менялись.

Устанавливаемый сервис кеширует результат разбора Markdown по пути, mtime/размеру и событиям Vault. После первого снимка отправляются только изменившиеся/удалённые карточки, страницы до 128 записей и ограничение размера запроса. Получатель хранит epoch/курсор; пропавший/устаревший индекс вызывает один полный снимок. Старый мост совместим с полными снимками; в новом издателе пустой цикл не публикует снимок. История и заметки сохраняют собственные курсоры; их поиск записей в Markdown этим изменением полностью не оптимизирован.

Остаются ограничения: начальный полный снимок до 1,5 МБ, совместимый полный снимок хранится на сервере и переписывается при изменениях, журнал дельт пока без автоматической компактации. Для очень большой Obsidian-библиотеки нужны пагинация первичной загрузки и политика хранения журнала.

- Новые Flutter-тесты проверяют облачную изоляцию, подделку LAN-пакетов, восстановление адреса, политику скачивания и подтверждение удаления, экран телефона с клавиатурой, инкрементальный мост, фоновый обмен без файлов, настоящий Node WebSocket ↔ TCP, большой зашифрованный ответ, неверный ключ, отмену, переподключение и отзыв пары.

Первая индексация нового/изменённого файла по-прежнему читает его целиком для SHA-256. На Windows она выполняется в isolate; на SAF — в нативном worker. Кеш атрибутов избавляет от повторного чтения неизменившегося содержимого. Изменённый файл передаётся целиком с докачкой: повторное использование его неизменившихся блоков ещё не реализовано. Режим без скачивания не отменяет первичную индексацию уже находящихся в общей папке файлов.

Не проверены на физическом устройстве: смена роутера, multicast конкретного Wi-Fi, системный запуск JobScheduler/Doze, уведомления/ограничения производителя, SAF при заполнении диска, многогигабайтные курсы и мобильный интернет. Публичного discovery/NAT traversal и аккаунтов нет. Ретранслятор требует сервера и одновременно доступных устройств; файлы на нём не сохраняются. Установочные пакеты этим изменением не выпускались.

Основание платформенных ограничений: [Android JobScheduler](https://developer.android.com/reference/android/app/job/JobScheduler), [ограничение dataSync](https://developer.android.com/develop/background-work/services/fgs/timeout). Сравнение модели ретрансляции: [Syncthing Relaying](https://docs.syncthing.net/users/relaying.html).
