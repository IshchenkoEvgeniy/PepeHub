## Подтверждение удаления

Удаление файла на одном устройстве создаёт запись об удалении. На принимающем устройстве существующая неизменённая копия остаётся в рабочей папке, а на экране **Устройства и общие папки** появляется **Подтвердить удаления (N)**. Запросы хранятся в локальной БД и переживают перезапуск; остальные файлы продолжают синхронизироваться.

- **Подтвердить удаление**: при выключенной истории файл удаляется без резервной версии; это явно указано в диалоге. Если история включена, копия перемещается в `.pepehub/p2p/versions` на Windows и Android в пределах заданных ограничений.
- **Оставить файл**: создаётся новая согласованная версия сохранённого файла. При следующем обмене он восстановится на других устройствах, где был удалён. Это явно указано в диалоге.
- **Отмена / закрытие страницы**: запрос остаётся в ожидании, файл сохраняется.

Запрос привязан к конкретным версиям. Если локальный файл изменился, старое подтверждение отклоняется. Если пришла более новая восстановленная версия, устаревший запрос удаляется. Одновременное независимое изменение и удаление по-прежнему сохраняет изменённый файл и сообщает о конфликте.

Новый отправитель не выдаёт записи удалений клиенту без признака `deleteApproval: 1`; файловый обмен остальными записями остаётся совместимым. Новый получатель запрашивает подтверждение и при получении записи удаления от прежнего отправителя. Подтверждение касается входящих удалений внутри общих папок; оно не перехватывает удаление через файловый менеджер на самом устройстве.

## Где хранятся передаваемые файлы

Отправитель читает ограниченные блоки непосредственно из выбранной папки. Предварительное копирование отправляемого медиа в данные приложения не требуется.

Получатель записывает блоки в служебную докачку **внутри выбранной общей папки**:

- Windows: `.pepehub/p2p/staging/<путь-хеш>-<хеш-содержимого>.part`;
- Android SAF: `.pepehub-transfer-<путь-хеш>-<хеш-содержимого>.part` в целевой подпапке.

После проверки полного SHA-256 эта докачка переименовывается в итоговый файл. Второй полной копии нового содержимого во внутреннем хранилище приложения не создаётся. После обрыва `.part` остаётся в общей папке для продолжения; он исключён из файлового индекса и автоматической библиотеки. При несовпадении SHA повреждённая докачка удаляется, прежний рабочий файл сохраняется.

Версии при замене или подтверждённом удалении сохраняются **только при включённой истории**, внутри служебной папки общей папки. По умолчанию история выключена. При включении исходные ограничения — 30 дней и 500 МБ. Прежние копии сохраняются при переносе до явной очистки или включения ограничений.

Прежний движок оставлял `.part` во внутренних данных приложения. При полном сканировании новая версия удаляет только известные прежние временные копии, для которых в общей папке уже проверено текущее содержимое. Незавершённая старая докачка переносится блоками в выбранную папку и продолжается от сохранённого смещения. Неизвестные файлы и единственная недостающая копия не удаляются. Результат очистки виден в журнале.

Для SAF нужен провайдер с прямой записью, определением длины и переименованием документов. Если провайдер этого не поддерживает, обмен сообщает об ошибке; скрытого обхода через полную копию в данных приложения нет. Реальное поведение провайдеров и обрывы питания ещё требуют аппаратной приёмки.

## Автоподключение к библиотеке

При добавлении/принятии папки можно выбрать **Автоподключение к библиотеке**. Для существующей папки откройте одноимённую кнопку в её карточке.

Режимы: **не подключать**, **по содержимому**, **книги**, **аудиокниги**, **видео**. В новом диалоге предложено определение по содержимому; ранее сохранённые общие папки остаются в режиме «не подключать» до изменения настройки. Выбор действует на этом устройстве независимо от второго.

Регистрация выполняется сразу для имеющихся файлов и после успешного получения изменений. Книги получают обычный подключённый корень, аудиокниги — ссылки на треки с сохранением существующего режима группировки, видео — курс с корнем этой папки. При обновлении сохраняются локальные ID, прогресс и ручная структура курса; переименования видео не подтверждаются автоматически. Незавершённые файлы, история версий и служебные каталоги не включаются в библиотеку. Поддерживаемые типы выбираются по расширению; изменение состава определяется по проверенным хешам.

Медиа не импортируется отдельной копией. На Android движок чтения может по-прежнему кэшировать **открытую** текстовую книгу/PDF для чтения — это существующий механизм читалки, не предварительный этап синхронизации всей папки.

Выключение автоподключения прекращает дальнейшую автоматическую регистрацию, сохраняя уже созданные библиотечные записи. Отсутствующие источники сохраняют историю, заметки и позиции согласно обычным правилам корней библиотеки. Неоднозначные старые соответствия, миграции изменённых аудиоизданий и сложные вложенные структуры остаются отдельными ограничениями прикладной синхронизации.
