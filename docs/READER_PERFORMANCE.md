# Оптимизация читалки после 0.22.1

25 октября 2026. Изменения включены в опубликованную [0.22.2+64](https://github.com/IshchenkoEvgeniy/PepeHub-Releases/releases/tag/v0.22.2-64) для Windows x64 и Android ARM64. [Описание выпуска](RELEASE_0222.md).

## Изменения

| Участок | Результат |
|---|---|
| `reader_page.dart`: позиция | Отчёты прокрутки обновляют положение и отдельные подписчики `ValueNotifier`. Текст, панель заметок и весь экран не перестраиваются каждые 250 мс. Возврат к закреплённому месту остаётся доступен. |
| Заметки | Преобразование координат заметок в непрерывную книгу кэшируется до изменения документа или списка заметок. В viewport заметки и сноски выбираются по индексу пересекающихся диапазонов. Сохраняется исходный приоритет перекрывающихся диапазонов. |
| `reader_viewport.dart`: измерение | Для сегментов, расположенных до текущей позиции прокрутки, больше не создаётся `TextPainter`. Измеряется только нужный сегмент. |
| Отметки глав | Поиск страниц глав стал бинарным. Результат кэшируется до изменения раскладки/границ глав. Painter сравнивает содержимое списков, а не только ссылки. |
| Нижняя шкала книги | Вместо отдельного виджета для каждой главы используется рисование. Статические отметки вынесены в отдельный `RepaintBoundary`; перемещение указателя не требует заново рисовать их. |
| Переходы поиска/закладок | `ReaderViewportController` переводит к позиции внутри уже рассчитанного окна. Состояние viewport и страницы сохраняются. Переход за пределы загруженного окна по-прежнему открывает новый участок — полная загрузка огромной книги ради редкого перехода не требуется. |
| Временные панели | Поиск, возврат после ссылки, начало длинной цитаты и ошибки показываются поверх области чтения. Они не меняют её размеры и не запускают перевёрстку. Плашки располагаются выше кнопок страниц/ползунка, чтобы можно было продолжить длинную цитату. |
| Размер окна | `ReaderLayoutFrame` показывает прежнюю раскладку во время изменения размеров, обрезая её по новым границам. Через 180 мс после последнего изменения выполняется новая раскладка. Перед этим сохраняется актуальная позиция прокрутки. |
| `epub.dart` | Нормализация растущего буфера для координаты ссылки вызывается только для ссылок; вычисление позиций изображений сохранено. |
| Запись переходов | Быстрые намеренные переходы объединяют чекпойнт и экспорт журнала с задержкой 350 мс. Сами события переходов остаются в памяти, позиция сохраняется отдельно; закрытие/пауза сбрасывают ожидающий чекпойнт. Переходы не засчитываются как прочитанный текст. |

## Дневное время чтения

`reading_daily_totals.dart` хранит производный числовой индекс интервалов. Это не второй источник истории: исходные записи `reading-session:*` сохраняются.

- При первом использовании существующие сессии индексируются партиями по 20. JSON разбирается в отдельном isolate; между партиями управление возвращается UI.
- SQLite-триггеры отмечают изменившиеся сессии. Учитываются обычные записи приложения, замены/удаления при синхронизации и смена ключа сессии. Повторная запись сессии заменяет её вклад и не удваивает время.
- Очередной запрос разбирает только изменённые сессии. Итог дня считается SQL-запросом по индексированным числовым границам интервалов, с отсечением по местной полуночи, масштабированием `activeMs` и исключением удалённых интервалов.
- Читалка обновляет число раз в 30 секунд, а не перечитывает всю историю при каждой смене главы. Временные ошибки позволяют повторить построение индекса; повреждённая JSON-запись не блокирует очередь.

Таблицы `reading_span_index_v1` и `reading_span_dirty_v1` — восстанавливаемый локальный кэш. Новых зависимостей не добавлено.

## Большие PDF

Ограничение автоматической текстовой статистики только документами до 100 страниц снято. Для больших PDF фоновая индексация начинается после открытия первой страницы с задержкой 600 мс. Native-чтения выполняются последовательно с уступкой управления между страницами.

Через каждые 32 страницы сохраняются числовые длины и смещения. При закрытии, фоне, открытой панели или переходе в текстовый режим работа прерывается, сохраняя достигнутый префикс. При возвращении индексация продолжается. До её окончания используется прежняя статистика по страницам/времени; частичный индекс не выдаётся за полный объём книги.

После завершения полный индекс публикуется, прежняя сессия закрывается и новая получает корректную систему координат. Время не дублируется, предыдущие пропущенные страницы не засчитываются как прочитанные. В кэше нет полного текста и геометрии всех символов. Сканы без текстового слоя и запрет копирования по-прежнему ограничивают статистику по знакам.

## Проверки

- Полный прогон приложения с настоящим Windows PDFium: **624 passed / 12 skipped**. Лог `.local/reader-performance-full.log`.
- После финальной замены виджетов нижней шкалы на рисование повторены **17 целевых тестов**, все прошли: навигация/восстановление, сноски, длинная цитата, заметки, оптимизации и большие PDF. Лог `.local/reader-performance-final.log`.
- Анализ `lib`, `test`, `integration_test`: **No issues found**. Лог `.local/reader-performance-analyze-final.log`.
- Экран чтения дополнительно проверен с загруженными Lora, Onest, Oswald и CormorantGaramond; снимок создаётся существующим тестом в `apps/pepehub/build/reader-010-dark.png`.

Новые сценарии `reader_performance_test.dart` проверяют:

1. Индекс диапазонов против прямой выборки на перекрывающихся и несортированных данных; непересекающиеся границы не включаются.
2. Поиск около конца списка из 10 000 сносок без перебора всего списка.
3. Отсутствие перерисовки одинаковых отметок глав и отсутствие виджета на каждую главу книги из 1000 глав.
4. Объединение быстрых изменений размеров.
5. Сохранение самого виджета текста при отчёте прокрутки; сохранение состояния viewport при переходе между результатами поиска и появлении плашки цитаты.
6. Точность дневного времени после замены, переименования, удаления и повреждения метаданных сессии.
7. Объединение экспорта журнала и обязательное сохранение последнего перехода при закрытии.

`pdf_index_progress_test.dart` использует настоящий PDFium: остановка после 32 страниц, продолжение до 140 с сохранением префикса; открытый просмотрщик PDF больше 100 страниц достраивает сохранённый индекс и оставляет ровно одну активную сессию с ненулевым объёмом текста.

## Ограничения

Это функциональная и алгоритмическая проверка. Время кадров, FPS, потребление батареи и максимальная память на физическом Android не измерялись. Первый перенос большой истории требует однократной индексации; дневное число появится после её завершения. Максимальные 20 000 страниц и библиотеки с многолетней историей отдельно не профилировались.

Из обсуждавшихся улучшений интерфейса в этот пакет не входят новое общее выделение через абзацы, нормализация поиска «е/ё», распознавание глав TXT, быстрые закладки и дополнительные горячие клавиши. Они требуют своих сценариев проверки координат и взаимодействий. Текущий пакет закрывает производительность и индексацию PDF.
