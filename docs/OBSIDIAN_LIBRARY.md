# Библиотека Obsidian в PepeHub

Реализация от 03.10.2026. Третий основной раздел «Библиотека» находится в том же меню, что «Книги» и «Аудиокниги». Он содержит карточки метаданных Obsidian, поиск, фильтр типа и редактор всех свойств. Наличие карточки не означает наличие файла для чтения или прослушивания.

## Изученная модель и архитектура

Источники — реальный `obsidian-habit-timer-main`: `src/types.ts` (`LibraryPropertyField`, `DEFAULT_LIBRARY_PROPERTY_ALIASES`), `src/library/property-schema.ts`, `src/store/StateManager.ts`, `src/services/cloudflare-companion-service.ts`, `src/media-modals.ts`, `cloudflare-companion/src/types.ts` и `cloudflare-companion/src/index.ts`.

В исходном PepeHub нет рабочего Telegram-клиента: Telegram-библиотека реализована в Obsidian-плагине и его Companion. Его `LibrarySyncItem` передаёт лишь часть данных и идентифицирует карточку по пути; отдельный Dashboard API также не содержит всех полей. Поэтому новый обмен переиспользует авторизацию, D1, настройки коллекций, шаблоны, YAML-алиасы и `processFrontMatter`, но хранит полный снимок и отдельную очередь команд. Он не читает, не подтверждает и не изменяет Telegram events/cursor, не использует прототип `SyncClient` PepeHub.

Реальные основные поля плагина:

| Поле | Значение |
| --- | --- |
| title | Название |
| author | Автор/авторы |
| genre | Жанр/жанры |
| series | Серия |
| seriesIndex | Номер в серии |
| status | Статус |
| total | Полный объём, страницы или длительность |
| progress | Прочитанный/прослушанный объём |
| rating | Рейтинг |
| cover | Ссылка на обложку |
| format | Формат, включая Audiobook |
| libraryType | Коллекция библиотеки |
| startDate | Дата начала |
| endDate | Дата завершения |
| season | Сезон |
| episode | Эпизод |
| queueOrder | Порядок в очереди |
| targetDate | Целевая дата |
| unit | Единица прогресса |

Схема передаётся самим плагином; таблица не задаёт ограничение сериализатора. Настроенные алиасы и реально присутствующие YAML-ключи сохраняются. Все дополнительные свойства, включая пустые, массивы, логические значения, вложенные объекты, `Time spent`, теги и пользовательские заметки в YAML, передаются целиком. Отсутствующие основные поля добавляются в снимок с `null`. Произвольный текст Markdown остаётся в Obsidian. Свойство обложки сохраняет ссылку Obsidian; локальное изображение дополнительно передаётся через защищённое хранилище Companion и кешируется в приложении.

Карточки коллекции `book` включают электронные, бумажные и аудиокниги. Аудиоформат определяется так же, как в плагине: `format` содержит `audio`/`аудио`. Отдельные коллекции с такими ID также поддерживаются. Другие медиа (фильмы, курсы) в эту вкладку не импортируются.

Слои Flutter: `LibraryService` → `LibraryMapper` / `ObsidianSyncService` → `LibraryRepository`. Репозиторий использует существующую транзакционную SQLite-таблицу `metadata`; файлы, чтение, аудиопозиции и текущий общий outbox остаются отдельными. Настройки соединения и данные разделены по хешу адреса и токена. Токен сохраняется только в `FlutterSecureStorage`.

## Правила обмена

- Obsidian публикует снимок автоматически каждые 30 секунд; приложение получает его при запуске, подключении и затем по выбранному интервалу (30 секунд по умолчанию), независимо от выбранного раздела.
- Ни подключение, ни периодический обмен не создают карточки для несвязанных локальных книг. Журнал и обложка явно связанной книги могут отправляться автоматически. Только сохранение редактора после «Добавить в библиотеку» ставит `create` в отдельную долговечную очередь.
- Если файл приложения уже имеет карточку в Obsidian, можно явно выбрать «Связать с существующей карточкой». Сопоставление не выполняется только по названию. Повторная команда для связанной записи открывает её метаданные.
- Сохранение связанных метаданных ставит `update` только для изменённых свойств. Для аудио локальная длительность и позиция переводятся из миллисекунд в минуты; файлы и локальные пути обложек не отправляются.
- У карточки появляется YAML `pepehub_id` (UUID). Переименование сохраняет идентичность. При копировании заметки с таким же UUID второй экземпляр получает новый ID. UUID и свойства новой карточки записываются одной операцией создания файла.
- Одна команда всегда повторяется с тем же `operationId`. Её receipt и обновлённый снимок фиксируются в D1 одной транзакцией. Потеря ответа и перезапуск не создают вторую карточку.
- Конкурентные изменения разных полей объединяются. Если в Obsidian изменилось то же поле относительно версии, открытой редактором, команда получает конфликт; приложение сохраняет локальную правку и показывает текущую версию Obsidian. Можно принять эту версию и затем внести новую правку.
- Удалённая из Obsidian карточка помечается соответствующим состоянием; фоновый обмен её не восстанавливает. Повторное добавление требует новой явной команды пользователя.
- Для применения команд Obsidian должен быть запущен. До подтверждения запись показывает «Ожидает Obsidian»; при сетевой ошибке очередь остаётся в SQLite.

## Установка и включение

Мост установлен в исходники локального плагина в `L:\Obs\MySecondBrain\.obsidian\plugins\obsidian-habit-timer-main`; плагин собран. Установщик можно повторять, он сохраняет остальные изменения исходников:

```powershell
.\scripts\install-obsidian-library-bridge.ps1 -PluginPath 'L:\Obs\MySecondBrain\.obsidian\plugins\obsidian-habit-timer-main'
```

Для другого checkout плагина укажите его путь. В `cloudflare-companion` нужно применить миграцию `0011_pepehub_library.sql` и `0012_pepehub_activity.sql`, подключить R2 bucket `COVERS` и развернуть обновлённый Worker:

```powershell
npm run db:remote
npm run deploy
```

На текущем подключении 03.10.2026 миграция уже применена, Worker опубликован: `https://habit-timer-companion.ghjcnj1122.workers.dev`, версия `96532477-465b-48cd-8283-40daff4bf094`. Развёртывание добавляет маршрут библиотеки поверх скачанной действующей серверной версии; остальные маршруты и cron выполняются прежним кодом. Это сохраняет существующий Telegram и не публикует незавершённые локальные изменения модулей проектов. Исходная версия для отката — `03a1d502-3960-46b7-925a-a1d06928628c`. Рабочая конфигурация этого развёртывания хранится в игнорируемом каталоге `.local/obsidian-library/habit-timer-companion`.

Windows-сборка находится в `apps/pepehub/build/windows/x64/runner/Release/pepehub.exe`. Для переноса приложения требуется весь каталог `Release`, включая DLL и `data`.

В плагине используются существующие `cloudflareWorkerUrl` и `cloudflareApiToken`; обмен PepeHub независим от `telegramMode`. Перезагрузите плагин в Obsidian. В приложении откройте «Библиотека» → «Подключить Obsidian» и укажите тот же HTTPS-адрес и API-токен Companion. Нельзя подставлять Telegram bot token вместо Companion API token. Для разработки разрешён HTTP только на localhost.

На этом ПК подключение PepeHub уже сохранено. Токен защищён Windows DPAPI в формате штатного `FlutterSecureStorage`; адрес находится в настройках SQLite. После перезапуска Windows-сборки все 31 карточка автоматически появились в разделе «Библиотека» и сохранены в локальной базе. Фильтр аудиокниг показывает 8 карточек; возврат к «Все» показывает 31. В реальном редакторе проверены основные поля, пустые даты и дополнительное YAML-свойство `Reading time`.

Для одной библиотеки должен работать один пишущий экземпляр моста. Синхронизация файлов vault между копиями Obsidian остаётся задачей используемого пользователем средства синхронизации. Снимок ограничен 1,5 МБ JSON, одна команда — 128 КБ; при превышении сервер отклоняет запрос, не обрезая данные. Для существенно больших библиотек понадобится постраничный протокол.

## Дизайн по концепту «полка.»

Интерфейс адаптирован по [предоставленному концепту](https://shelf-reading-dashboard.ghjcnj1122.chatgpt.site). Все три раздела используют общую графитовую палитру, фиолетовый акцент, шрифт Manrope и боковую навигацию. Сохраняется выбранная пользователем светлая, тёмная или системная тема; для нового профиля по умолчанию используется тёмная. Лицензия Manrope OFL включена в приложение.

В разделе Obsidian показаны реальные счётчики коллекции и статусов, поиск по названию, автору или серии, фильтры формата и статуса, сортировка и переключение списка/карточек. На широком экране выбранная запись открывается в правой панели; на узком — сразу в полном редакторе. Редактор группирует основные свойства, прогресс и дополнительные поля, сохраняя все исходные ключи и пустые значения. На телефоне навигация помещена в выдвижное меню, карточки статистики компактнее, а таблица заменена строками без горизонтальной прокрутки.

Счётчики не подставляют демонстрационные данные: неизвестный статус остаётся неизвестным, прогресс требует указанного объёма, а годовая цель появляется только после ввода пользователем и сохраняется локально для текущего соединения. Стандартный статус плагина «Чтение» учитывается как работа в процессе. Ссылки на сетевые обложки отображаются с резервной иллюстрацией; ссылки Obsidian на локальные изображения используют эту иллюстрацию.

Проверки дизайна охватывают ширины 390, 1100 и 1440 пикселей, масштаб текста 140%, поиск по автору и серии, сброс фильтров, пустые свойства, отсутствие исходящих команд при просмотре, прежние коллекции и избранное. Снимки интерфейса для визуальной проверки: `apps/pepehub/build/shelf-desktop.png`, `shelf-mobile.png`, `library-dark.png` и `library-light.png` (тестовые данные). Windows-приложение проверено с подключённой библиотекой из 31 записи.

После обновления дизайна полный Flutter suite: 131 passed, 4 skipped. Дополнительная проверка редактора на экране 390 × 844 с масштабом текста 140% успешна.


## Журнал, обложки и настройки в 0.16.0

В настройках приложения доступны 10 палитр, светлый/тёмный/системный режим, масштаб текста, компактность, уменьшение анимаций, дневная цель (0 отключает её), ручной обмен или интервалы 30/60/300 секунд. Журнал и обложки можно отключать отдельно.

Журнал доступен из «Настройки», статистики библиотеки и карточки книги. Он показывает дни, длительность, прогресс в исходных единицах, заметки и источник записи; есть поиск, фильтры и правки. Для локального файла требуется явное связывание с карточкой Obsidian. Чужие карточки тоже показывают полученный журнал, но не создают локальных файлов книг.

Мост читает таблицы `### 📖 Progress`, `Журнал чтения` и `Журнал прослушивания`. Старые строки получают скрытый UUID; видимые ячейки, дубликаты отдельных занятий и остальные разделы сохраняются. Приложение экспортирует реальные интервалы активности, исключает дублирующие итоги аудиоплеера, сохраняет миллисекунды и часовой пояс и делит ручные занятия в полночь. Страницы, символы и минуты не подменяют друг друга. Для старых строк без времени начала приложение показывает день без выдуманных часов и без оценки покрытия аудиокниги.

Протокол `/api/pepehub/library/activity` хранит версионные изменения, удаления, курсор и долговечные ответы команд. Повтор после потери ответа не добавляет занятие второй раз. Одновременные правки требуют выбора одной из двух версий. Конфликты доступны и в приложении, и командой плагина «PepeHub: разрешить конфликты журнала». Изменения времени отражаются в нативной статистике и свойстве `Reading time`/`Time spent` Obsidian.

Локальные обложки Obsidian преобразуются в PNG до 640 px и передаются в приватный R2 namespace профиля. В приложении копии проверяются по SHA-256 и сохраняются по namespace соединения. Новая обложка связанного файла и выбор картинки в редакторе Obsidian передаются обратно в `PepeHub/Covers`, с сохранением ссылки в YAML. Сетевые HTTP-ссылки продолжают отображаться как ссылки; приватные копии не публикуются через общий маршрут `/covers`. Файлы книг и аудио не выгружаются.

Проверки 0.16.0: полный Flutter suite — 142 passed, 4 skipped; анализ без замечаний; 22 серверных теста и TypeScript typecheck; 7 целевых тестов плагина и успешная сборка. Проверены повтор доставки, конфликты, изоляция профилей, миллисекунды, полночь, старый русский журнал, CRLF, заметки с переносами и разделителями, обложки и офлайн-кеш.

Живой обмен 0.16.0 проверен 03.10.2026 после перезагрузки обновлённого плагина: 31 карточка, 29 обложек и 14 существующих записей журнала переданы в Companion. SHA-256 загруженной обложки совпадает; доступ без токена возвращает 401, прежний `/health` — 200. Очередь журнала сохранена в фактическом каталоге плагина. Windows release 0.16.0 успешно собран.


## Автозаполнение и заметки в 0.17.0

При создании карточки приложение читает индекс и метаданные исходного файла, сохранённую позицию и статистику. Даты `startedAt`/`finishedAt` попадают в свойства начала/завершения; обложка из файла или папки загружается автоматически, если включён обмен обложками. PDF использует страницы, текст без точного количества страниц — символы, аудио — минуты. Общая длительность аудио определяется на Android через MediaMetadataRetriever, включая файлы SAF; фактическое время прослушивания берётся из журнала и не зависит от скорости воспроизведения. Неизвестная длительность не заменяется нулём. Данные автоматически заполняют пустые поля связанных карточек и обновляют ранее заполненные приложением поля, сохраняя ручные правки и алиасы конкретной карточки.

`/api/pepehub/library/notes` хранит цитаты, комментарии, теги, персонажей, цвет и привязку к тексту или аудиопозиции. Используются отдельные версии, устойчивые UUID запросов, курсор и удаления. Одновременные правки сохраняются до выбора версии. Заметки книги импортируются в нативный список заметок после связывания файла; неподходящая привязка не переводит читалку к выдуманному месту. Все полученные заметки доступны через «Настройки → Заметки Obsidian», даже без локального файла.

В Obsidian обычный текст карточки аннотируется скрытыми блоками `pepehub-note` с UUID. Видимое содержимое, YAML и разделы журнала сохраняются. Передаваемые цитаты и аудиозаметки отображаются обычным Markdown; можно редактировать комментарий, цитату, теги и персонажей, сохраняя разделители HTML. Удаление блока передаётся как удаление заметки. Повреждённые разделители останавливают обмен этой карточки с сохранением исходного текста. Конфликты доступны командой «PepeHub: разрешить конфликты заметок».

Для обновления моста применяется `scripts/install-obsidian-library-bridge.ps1`, сборка плагина и миграция `003_pepehub_notes.sql` (в checkout Companion — `0013_pepehub_notes.sql`). Используемый плагин уже обновлён на диске; после установки требуется перезапуск Obsidian. Companion сохраняет прежний legacy Worker и добавляет маршруты моста. Живая проверка новой версии: библиотека доступна с токеном, `/notes` возвращает version 1, запрос без токена — 401, прежний `/health` — 200.
