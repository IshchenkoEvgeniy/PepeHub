## Повторная сборка

Из корня проекта в PowerShell:

```powershell
./scripts/build-android.ps1
```

По умолчанию собирается ARM64 release APK. Для всех поддерживаемых Flutter Android ABI:

```powershell
./scripts/build-android.ps1 -Architecture universal
```

Скрипт применяет локальные JAVA_HOME, ANDROID_HOME, ANDROID_USER_HOME, GRADLE_USER_HOME и PUB_CACHE только к текущему процессу и его потомкам. Системный PATH не изменяется. SDK/JDK нельзя переносить из `.tools` без обновления среды. Если исходники скопированы на другой компьютер, необходимо отдельно установить инструменты и выполнить `flutter pub get`.

Результат Flutter для ARM64: `apps/pepehub/build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`; для universal — `app-release.apk` в той же папке. Скрипт проверяет подпись и ZIP-выравнивание, копирует APK и SHA-256 в `dist`. Package ID — `app.pepehub.pepehub`. Минимальная версия — Android 7.0 (API 24), target SDK 36. Текущая версия приложения 0.15.0; versionCode ARM64 APK — 2043 (Flutter добавляет префикс ABI к базовому 43).

ARM64 использует штатный `--split-per-abi`: это исключает лишние JNI-библиотеки других архитектур. Сборка выполняет `pub get`, чтобы обновить регистрацию плагинов после integration_test; `--no-pub` здесь намеренно не используется.

## Подпись и установка

Сборка release оптимизирована, но подписана **локальным тестовым Android-ключом**, как задано в build.gradle.kts. Она предназначена для ручного тестирования, а не публикации в Google Play. Ключи не включаются в дистрибутив. Для последующих обновлений этого же приложения нужно сохранять тот же ключ; подпись production следует настроить отдельно перед публичным выпуском.

Скопируйте APK на ARM64-телефон и откройте его. Android может запросить разрешение установки из выбранного источника. Через USB с включённой отладкой:

```powershell
. ./scripts/android-env.ps1
adb devices
adb install -r ./dist/PepeHub-0.5.4-android-arm64-test.apk
```

Подключение устройства и USB-отладка выполняются пользователем. Сборка APK не подтверждает работу на конкретном телефоне.

## Проверка на устройстве

1. Запустить приложение, импортировать EPUB/FB2/TXT и PDF через системный выбор файла.
2. Перейти к другому абзацу/странице, закрыть приложение и проверить восстановление позиции.
3. Импортировать аудио, проверить воспроизведение, паузу, перемотку и журнал.
4. Заблокировать экран, проверить фоновое аудио и управление из уведомления, прерывание звонком/гарнитурой.
5. Проверить синхронизацию карточек и сессий с доступным HTTPS API. В release локальный HTTP запрещён; `localhost` телефона не является ПК. Для файлов и позиций межустройственная синхронизация ещё не реализована.

Эмулятор, реальный телефон и перечисленные аппаратные сценарии пока не проверены. Матрица форматов и её ограничения — в [FORMATS.md](FORMATS.md).
