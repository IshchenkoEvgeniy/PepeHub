# Обложки и .pepehub — 0.6.0

## Обложки

Обложка отображается в библиотеке, на экране аудиокниги и в Android MediaSession. На экране плеера появилась кнопка «Выбрать обложку»: выбранное изображение проверяется декодером, уменьшается до ширины 512 px и сохраняется в локальном кэше. Новое имя файла исключает показ старого изображения из кэша Flutter/Android. Аудиофайлы не копируются.

Автопоиск: рядом с первым треком, затем выше по папкам CD/Disc/Disk/Диск/Часть/Part/Том с номером (до четырёх уровней). Приоритет имён cover, folder, front, обложка, затем остальные JPG/JPEG/PNG/WebP. Подъём останавливается на папке книги; изображения соседней книги не используются. Выбор сохраняется между запусками.

Если отдельного изображения нет, Android извлекает встроенную обложку через MediaMetadataRetriever. Поддержка зависит от контейнера/провайдера Android. Для обычных файлов Windows добавлен ограниченный разбор ID3v2.3/2.4 APIC и M4A/M4B covr/data: аудиоблоки пропускаются через seek. Сложные ID3 с unsynchronisation/extended header/compression не разбираются; доступен ручной выбор. Изображение ищется по первому треку; сбор всех картинок из каждого трека не выполняется. Изображения из отдельной папки Smart AudioBook Player пока не сопоставляются.

Ошибки автоматического поиска/декодирования не препятствуют воспроизведению. Ручной выбор ограничен 16 МиБ. Маленькие PNG кэша включаются в резервный JSON (до 2 МиБ на изображение), поэтому после восстановления не нужен первоначальный выбранный файл. Старые версии кэшированных картинок пока не очищаются автоматически.

## Снимки

Подключённые корни получают `.pepehub/library-<время>-<uuid>.json`: позиции, скорость, состав треков, карточки, сессии и кэшированные обложки. Снимки не содержат абсолютных путей к аудиофайлам. Сохраняются раз в минуту и при завершении сессии/паузе/остановке; первичное сохранение позиции в SQLite остаётся каждые 10 секунд.

Хранятся последние 10 снимков нового формата имени. Чужие файлы и старые UUID-снимки 0.5.x не удаляются. Запись идёт в `.partial`, затем файл переименовывается; ротация выполняется только после успешной записи. Снимок ограничен 16 МиБ. Если папка недоступна, переполнена или провайдер не поддерживает запись/переименование, приложение показывает ошибку в плеере, сохраняет прогресс в SQLite и повторяет попытку при следующем checkpoint. Синхронизация отсутствует.

Android-канал доступа к папкам теперь живёт вместе с FlutterEngine, а не экраном Activity. Для фоновой работы используется applicationContext; экран хранится как слабая ссылка только для системного выбора папки. При уничтожении движка канал закрывается.

## Восстановление

«Папки библиотеки» → нужный корень → «Восстановить снимок» → выбрать JSON из `.pepehub`. Показаны дата, количество книг/сессий и предупреждение о замене позиций/обложек. После подтверждения создаётся резервный снимок текущих данных; отказ записи отменяет восстановление.

Исходные книги должны быть подключены. Сопоставление проверяет число треков, относительные имена и размеры. При старых ID сначала проверяется их совместимость; при новых ID требуется единственный подходящий состав. Неоднозначность/изменение состава прекращает восстановление. Это не криптографическая идентификация содержания: замена файла на другой с тем же именем и размером не обнаруживается.

Позиции и обложки заменяются, сессии объединяются по ID без удвоения. Новые сессии, отсутствующие в снимке, сохраняются. Данные SQLite восстанавливаются транзакционно; ошибочный трек/позиция/конфликт сессии откатывает изменения. Аудиофайлы не изменяются. Карточки включены в снимок для информации, но их названия/статусы пока не восстанавливаются. Восстановление с пустой базой: сначала подключить исходные папки, затем применить снимок.

## Проверки

Автотесты: приоритет соседних изображений, CD/Disc, декодирование/кэш и смена изображения, отказ доступа SAF, ID3 APIC/M4B covr и повреждённые метаданные, ротация без удаления чужих JSON, ограничение частоты, восстановление позиции и сессий, новые ID, неоднозначный/изменённый состав и откат некорректной позиции. Нативные Android MediaMetadataRetriever/SAF и длительную запись при заблокированном экране необходимо проверить на телефоне.

Спецификации: [ID3v2.3 APIC](https://id3.org/id3v2.3.0), [метаданные QuickTime](https://developer.apple.com/documentation/quicktime-file-format/metadata_atoms_and_types).
