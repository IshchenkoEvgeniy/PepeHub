# Экспорт книг и аудиокниг: статусы и удобный ввод

Изменения входят в выпуск 0.26.0+74 и включают Flutter-приложение, мост библиотеки и поддержку единиц прогресса в Habit Timer. Companion в рамках этого обновления не разворачивается.

- Коллекция передаёт свои `planned/active/paused/finished` статусы и поддерживаемые единицы. Приложение записывает настроенные в Obsidian названия. Старые снимки без этих необязательных полей продолжают приниматься.
- Начатая книга получает активный статус, если пользователь не задал другой. Завершение читалки и событие `completed` последнего трека издания дают завершённый статус и дату. `chapter_completed` завершением книги не считается. Ручной выбор «В планах» для аудио сохраняется. Время чтения/прослушивания берётся из журнала без прежнего лимита в 100 000 записей.
- PDF использует страницы, аудио — минуты (или часы существующей карточки). EPUB/FB2 используют проценты, если мост их поддерживает; символы остаются служебными сведениями. Уже указанное в Obsidian количество страниц сохраняется и используется для пересчёта доли текста.
- Разные аудиоиздания не складываются как главы одного издания: общий объём и позиция относятся к последнему открытому изданию.
- Авторы, жанры и теги вводятся метками; подсказки авторов, жанров, серий, языка и издательства берутся из полученной библиотеки и доступны офлайн. Имена внутри списков, содержащие запятую, сохраняются целиком. Даты выбираются календарём, оценка — по кнопке, обложка имеет предпросмотр. Служебные YAML-ключи вынесены в подробности, дополнительные свойства свёрнуты.
- Разбор имени аудиокниги предлагает автора, название, номер части и чтеца с подтверждением каждого поля. Android artist не записывается автоматически как автор; для автора используется writer. Метаданные треков сопоставляются по частоте встречаемости.
- При связывании существующей карточки показываются обе версии полей. Для каждого свойства выбирается автообновление с сохранением ручных правок, приложение или Obsidian. Прогресс, объём и единицы выбираются совместно. Для новой карточки выбор коллекции определяет папку создания.
- Пустые нетронутые поля не стирают значения шаблона. Явно очищенные исходные данные передаются в `clearFields`; обычный update с null продолжает очищать свойство.
- Автоматически рассчитанные изменения отправляются в текущем цикле обмена. SQLite-триггеры схемы 4 отмечают изменения источников по книгам. Неизменившиеся данные кешируются на 10 минут; изменения сессий, позиций, ручных статусов, журнала Obsidian, треков и длительностей сбрасывают кеш. Очереди, базовые снимки и сам кеш не вызывают повторный расчёт.

Мост устанавливается скриптом `scripts/install-obsidian-library-bridge.ps1`. Он также добавляет проценты и символы в единицы Habit Timer, сохраняя другие изменения исходников. На этом ПК исходники обновлены и плагин собран; для загрузки нового main.js нужен перезапуск плагина/Obsidian. Существующий Companion принимает дополнительные поля протокола, поэтому для них не нужна отдельная миграция D1.

Проверка: анализ Flutter/TypeScript, сборка Windows и плагина, ручной предпросмотр формы с вымышленными данными на ширине 390 px, проверка фактического SQL схемы на SQLite 3.53.1. Автоматические Flutter- и TypeScript-тесты по указанию пользователя не запускались. Регрессионные сценарии добавлены в `library_export_metadata_test.dart` и уточнены в `automatic_metadata_test.dart`.
