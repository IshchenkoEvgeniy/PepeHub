# Аудиоплеер: журнал реализации

14.09.2026 · Первый цикл · Версия приложения 0.4.1+5.

План: [задачи W0–W12](AUDIOBOOK_IMPLEMENTATION_PLAN.md). В этом цикле реализуется основа W1; весь этап A и многотрековый интерфейс ещё не завершены.

## Изменения

- `lib/audio/models.dart`: отдельные издание, трек, глава и AudioLocator с проверкой адреса и границ. Позиция содержит ID книги/издания/трека и ревизию манифеста; пути в неё не входят.
- `lib/audio/audio_library_repository.dart`: регистрация текущего однофайлового импорта, независимые позиции изданий, общий физический ресурс по хешу, проверка принадлежности трека и ревизии при сохранении.
- Схема SQLite 3: audio_editions, audio_resources, audio_tracks, audio_chapters, audio_progress. Таблицы истории/закладок/настроек будут добавлены с соответствующим поведением; весь W1.2 пока не закрыт.
- Транзакционный перенос аудиокарточек схемы 1/2; сохранение ID карточек, сессий, outbox и старых таблиц. Карточка без файла получает издание без фиктивного трека. Электронные книги не превращаются в аудиотреки.
- Импорт регистрирует аудиотрек в той же транзакции, что и карточку. Плеер читает/пишет новую позицию; устаревший API позиции по хешу удалён.
- После stop сброс состояния движка больше не должен записывать нулевую позицию поверх сохранённой. Нативный тест проверяет stop → повторное открытие.

## Обновление и резервная копия

Новая рабочая база — `pepehub-v3.sqlite` в каталоге данных приложения. При первом запуске существующая `pepehub.sqlite` копируется согласованным SQLite `VACUUM INTO`, включая зафиксированные данные WAL. Исходная база не мигрирует на месте: приложение 0.4 продолжает понимать её старую схему. Аудиофайлы не перекопируются.

Перед миграцией создаётся проверенная `quick_check` копия `backups/before-v3-<UUID>.sqlite`. Копирование и открытие выполняются вне UI isolate. Ошибка резервирования прекращает переход; данные не сбрасываются. Миграция и номер схемы фиксируются одной транзакцией. Новая версия отказывает в открытии более новой неизвестной схемы.

После успешного переноса изменения старой и новой базы автоматически не объединяются. Не продолжайте попеременно вести библиотеку в 0.4 и 0.4.1: новая версия не перечитывает старую базу при каждом запуске.

Резервная копия содержит БД, но не сами аудиофайлы и не защищённые системные ключи. Для полного переноса устройства нужны отдельный экспорт файлов и настройка доступа; это задача последующих этапов.

## Восстановление

1. Полностью закрыть приложение и остановить воспроизведение. Сохранить весь текущий каталог данных, включая SQLite WAL/SHM и аудиофайлы, в отдельное место.
2. Для возвращения к исходному состоянию 0.4 использовать сохранённую старую базу с совместимой версией приложения. Новые позиции 0.4.1 в неё не переносились.
3. Для восстановления снимка в 0.4.1 использовать отдельный каталог восстановления: поместить выбранный `before-v3-*.sqlite` под именем `pepehub.sqlite`, затем открыть его новой версией через штатный путь подготовки базы. Проверка этой процедуры автоматизирована на тестовом каталоге.
4. На телефоне нет пользовательского экрана выбора каталога/восстановления: работа с закрытым каталогом приложения пока требует технического доступа. Готовый пользовательский backup/restore UI ещё не реализован. Не удалять приложение и не очищать его данные ради обновления APK.

## Проверки 0.4.1

- `flutter analyze --no-pub`: замечаний нет.
- `flutter test --no-pub`: 29 тестов прошли, 1 пропущен. Включены импорт на новой модели, копия с открытым WAL, повторное открытие без повторного переноса, восстановление из backup, откат ошибки миграции и защита неизвестной схемы.
- `flutter test integration_test/native_audio_test.dart -d windows`: 2 теста прошли — запуск на отдельной дисковой базе и реальный декодер WAV с seek, скоростью, сессией, stop и повторным открытием позиции. Тест не открывает пользовательскую Windows-библиотеку.
- `npm test`: 10 тестов прошли; `npm run typecheck`: успешно. Серверный контракт не менялся.

libmpv при нативном тесте по-прежнему сообщает о свойстве `osc` и файловом кэше; проверка локального WAV прошла. Эти сообщения не считаются проверкой будущего сетевого плеера. Набор тестов не доказывает поддержку всей матрицы кодеков.
