# Аудит аудиоплеера — 18 октября 2026

Проверены управление аудиокнигой, очередь команд, состояние системного плеера, восстановление декодера, позиция и скорость, таймер и завершение контроллера. Исправления после **0.21.2+54** опубликованы отдельным выпуском [0.21.3+55 для Windows и Android](https://github.com/IshchenkoEvgeniy/PepeHub-Releases/releases/tag/v0.21.3-55) по следующему запросу пользователя. [Пакеты, подписи и журнал выпуска](APP_UPDATES.md).

## Найдено и исправлено

| Сценарий | Прежнее поведение | Исправление |
| --- | --- | --- |
| «Стоп → Play», включая системные кнопки | Stop освобождал декодер и сбрасывал доступность Play; позиция в интерфейсе могла стать нулевой | Сохраняется точка и скорость, источник освобождается, явный Play снова загружает сохранённый трек |
| Тайм-аут команды | Контроллер считал себя остановленным, а системная панель продолжала показывать воспроизведение | Состояние системного плеера немедленно обновляется при отказе декодера |
| Ошибка при восстановлении | Неудачная первая попытка оставляла Play отключённым | Исходная точка сохраняется, повторный Play может создать следующий декодер |
| Ошибка декодера / отказ запуска | Оставались признаки воспроизведения и уже непригодный источник | Остановка статистики, публикация паузы, ограниченная попытка Stop и восстановление отдельным новым плеером |
| Отказ Seek / изменения скорости | `just_audio 0.10.6` меняет Dart-позицию, скорость и playing до подтверждения нативной команды; отказ мог сохранить непроигранную позицию или неподтверждённую скорость | Ошибка нативной команды сохраняет точку перед действием; неподтверждённое состояние не записывается как успешное |
| Ошибка после ручной перемотки на паузе | Сброс декодера в Idle мог заменить выбранную позицию нулём | Запоминается последняя корректно наблюдавшаяся позиция, включая ручную перемотку и загрузку |
| Открытие другой книги после отказа | Сначала предпринималась повторная загрузка уже недоступной прежней книги; новая книга не открывалась | Для новой книги создаётся декодер без восстановления прежнего источника |
| Stop при недоступном источнике | Команда Stop сама пыталась восстановить и открыть неисправный источник | Stop может завершить логическое воспроизведение и сохранить позицию без повторной загрузки |
| Возврат после повторного открытия | Округление позиции декодером на ±1 мс отменяло сохранённый возврат после таймера | Намерение проверяется по сохранённому прогрессу и идентичности трека, возврат рассчитывается от сохранённой точки. Новый синхронизированный прогресс отменяет старое намерение, включая изменения внутри того же трека |
| Медленное затухание таймера | Каждый тик раз в 250 мс добавлял ещё один нативный запрос громкости | Отдельная очередь объединяет ожидающие изменения; остаются выполняемый и последний ожидающий запросы. Pause и Seek не ждут эту очередь |
| Отмена затухания | Поздний ответ старой команды мог снова уменьшить громкость после отмены | Изменения и восстановление выполняются по порядку; последняя команда восстановления имеет приоритет |
| Отказ / зависание громкости | Необработанный Future либо накопление запросов | Ошибка отображается; ожидание ограничено тайм-аутом. Восстановление сохраняет исходную громкость, включая Stop после тайм-аута |
| Закрытие во время определения длительности | Звук продолжался до окончания независимой проверки файла | Сначала ставится пауза и сохраняется позиция, затем ожидается завершение проверки |
| Повторное закрытие и запоздавшие команды | Повторный dispose, работа уже закрытого декодера и уведомления закрытого ChangeNotifier | Один Future завершения, запрет новых команд и защищённые уведомления |

## Проверки

- Добавлены **19 регрессионных сценариев** в `apps/pepehub/test/audio_player_regressions_test.dart`. Ошибки воспроизводились до соответствующих исправлений; отдельный сценарий защищает исходную громкость после Stop при тайм-ауте затухания. В `audio_resume_controller_test.dart` дополнена проверка нового синхронизированного прогресса внутри того же трека.
- Сохранены проверки предыдущих исправлений: возврат после таймера через файлы, однократное применение, перезапуск, ручная навигация, отсутствие источника, аудиофокус, поздние ответы старого декодера и медленный внешний экспорт.
- Полный Flutter: **500 passed / 12 skipped**, лог `apps/pepehub/build/audio-player-audit-full.log`. Набор проверок контроллера: **41 сценарий** (включён в общий прогон).
- Отдельные прогоны: `audio-player-audit-before.log`, `audio-player-audit-controls-before.log`, `audio-player-audit-native-errors-before.log`, `audio-player-audit-rounding-before.log`, `audio-player-audit-final.log` в `apps/pepehub/build/`.
- Нативная проверка Windows: **1 passed**, `apps/pepehub/integration_test/audio_transport_regressions_test.dart`, сгенерированные бесшумные WAV и отдельная временная SQLite. Проверены реальные Stop/Play, переходы между файлами, скорость, сохранение и возврат после таймера. Лог: `apps/pepehub/build/audio-player-audit-native.log`. Движок также выдаёт предупреждения `osc` и `file cache`; проверенные операции от них не отказали.
- Dart-анализ `lib`, `test` и нового нативного сценария: **No issues found** (`audio-player-audit-analysis.log`).

Первая сборка нативного теста обнаружила пустой `CMAKE_CXX_FLAGS_DEBUG` и закреплённый путь установки `runner/Release` в ранее созданном кеше Windows CMake. Восстановлены стандартные `/MDd /Zi /Ob0 /Od /RTC1` только в генерируемом `build/windows/x64/CMakeCache.txt`; для запуска подключены установленные Debug CRT и UCRT. Нативный тест устанавливался в `runner/Debug`. Публичные пакеты в `dist/online/0.21.2-54` не изменялись.

После нативной проверки восстановлен путь установки `runner/Release` и заново собран обычный `lib/main.dart` с новым значением `PEPEHUB_AUDIO_AUDIT=2026-10-18-final`, чтобы локальный каталог Release содержал приложение с исправлениями, а не тестовую оболочку. Windows Release: **успешно**, `apps/pepehub/build/windows/x64/runner/Release/pepehub.exe`; лог `audio-player-audit-release.log`. После аудита по отдельному запросу повышена версия и опубликован выпуск **0.21.3+55** с повторной сборкой обеих платформ.

Принудительно перелинкован генерируемый Release EXE: ранее кеш установки Debug заменил его, а обычная инкрементальная сборка не обновляла. Проверены отсутствие Debug CRT-зависимостей в EXE, отсутствие `kernel_blob.bin` и наличие нового AOT `data/app.so`. SHA-256 публичных APK/ZIP совпадают с опубликованным выпуском 54. Сторонний ANGLE содержит прежний вспомогательный `zlib.dll` с Debug CRT-зависимостью; файл присутствует и в опубликованном архиве, прямых импортов из остальных EXE/DLL не обнаружено. Состав этого стороннего пакета не менялся.

Физический Android не подключён. Звонки, Bluetooth, фактическая работа SAF/SD-карты, фон и конкретный проблемный файл на телефоне остаются аппаратной проверкой. Успешные проверки с моделируемыми отказами не означают проверки всех прошивок и аудиоформатов.
