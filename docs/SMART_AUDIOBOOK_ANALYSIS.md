# Аудиокниги: анализ Smart AudioBook Player и PepeHub

Дата: 14.09.2026. Основание: пользователь подтвердил работу аудио в Android-сборке и запросил функциональность уровня Smart AudioBook Player. Результат анализа — [отдельное ТЗ](AUDIOBOOK_TZ.md), а не заявление о готовности этих возможностей.

## Метод и ограничения

Изучены официальная карточка Smart AudioBook Player в Google Play, документация Android и используемых Flutter-библиотек, исходники PepeHub 0.4.0. Smart AudioBook Player не устанавливался для сравнительного прогона. Не проверены все его экраны, настройки и различия Basic/Full. Пользовательское подтверждение работы PepeHub не заменяет испытания звонков, Bluetooth, длительного фона и всей матрицы кодеков.

## Что подтверждено у ориентира

Официальное описание указывает библиотеку из подпапок, скорость воспроизведения, статусы книг, обложки из интернета, закладки, список персонажей, автоматическую паузу при засыпании с продолжением встряхиванием, историю воспроизведения для восстановления позиции, Chromecast, виджет и сохранение отдельного прогресса книг. Ответ разработчика в карточке также упоминает выбор книг через Android Auto. Источник: [Smart AudioBook Player — Google Play](https://play.google.com/store/apps/details?id=ak.alizandro.smartaudiobookplayer&hl=en), проверен 14.09.2026.

Конкретные алгоритмы автоматической перемотки, пределы усиления звука, форматы встроенных глав, набор эквалайзеров и точные жесты этой проверкой не установлены. Их нельзя выдавать за подтверждённые свойства конкурента. Ниже и в ТЗ такие решения являются предлагаемым поведением **PepeHub**. Копирование оформления не требуется.

## Разрыв с текущей реализацией

| Область | Что есть в PepeHub | Что требуется |
| --- | --- | --- |
| Модель книги | Один импортированный аудиофайл — одна карточка | Издание с упорядоченными треками и главами; единый прогресс |
| Импорт | Копирование, SHA-256, проверка заголовка; восемь групп расширений | Папки/несколько файлов, предпросмотр порядка, метаданные, восстановление доступа |
| Плеер | Play/pause, ±15 секунд, 0.5–3×, локальная позиция | Навигация по книге, точная перемотка, оставшееся время, настройки для книги |
| Android | AudioService, speech-конфигурация, mediaPlayback service в manifest | Аппаратно подтверждённые фон, фокус, гарнитура, восстановление и согласованные системные команды |
| Таймер | 15/30/60 минут, обычный Timer | Произвольный интервал, конец главы, затухание, продление, понятное восстановление |
| Защита позиции | Checkpoint раз в 10 секунд, сохранение при действиях | История переходов, отмена, закладки, единая позиция между файлами |
| Библиотека | Название, автор, статус, поиск | Обложка, чтец, серия, длительность, доступность файлов и продолжение последней книги |
| Учёт времени | Реальное активное время, сохранение сессий | Разделение прогресса и времени, политика коротких пауз, часовые пояса, проверка отказов |
| Синхронизация | Карточки и сессии; позиции и файлы локальные | Прогресс, закладки, манифесты, R2, конфликты между устройствами |
| Obsidian | Экспорт и модуль управляемых Markdown-блоков | Рабочий мост, автоматическое обновление и ссылки на аудиопозиции |
| Дополнительные поверхности | Основной экран и мини-плеер | Виджет, автомобильный интерфейс; Cast отдельным этапом |

Проверенные участки: `apps/pepehub/lib/media/audio_controller.dart`, `asset_store.dart`, `listening_clock.dart`, `apps/pepehub/lib/data/database.dart`, `contracts/protocol.ts`, Android manifest; также [README](../README.md) и [матрица форматов](FORMATS.md).

## Вывод по архитектуре

Переписывать приложение целиком сейчас не обосновано. Flutter, SQLite, действующий импорт и механизм повторяемых операций можно сохранить. Основная работа — новая модель аудиокниги и разделение ответственности текущего AudioController: очередь, позиции, таймер, учёт времени и системные команды должны иметь отдельные проверяемые компоненты.

`audio_service` предоставляет обработчик фонового аудио и системных команд, включая Android Auto; приложение должно само реализовать очередь и поведение. `just_audio` остаётся кандидатом на движок. Наличие API не доказывает качество реализации на устройстве. Windows требует собственного адаптера системного управления: поддержку Android-плагина нельзя автоматически переносить на ПК. Источники: [audio_service](https://pub.dev/packages/audio_service), [just_audio](https://pub.dev/packages/just_audio).

Android рекомендует размещать проигрыватель и MediaSession в сервисе, независимом от Activity. Уже используемый AudioService следует проверить на выполнение требований; отдельный сервис на Kotlin/Media3 вводить только при документированном ограничении адаптера, без двух одновременно работающих плееров. Источник: [фоновое воспроизведение Android](https://developer.android.com/media/media3/session/background-playback).

Главные риски проекта — потеря позиции, путаница порядка файлов, неверное возобновление после прерывания и конфликт прогресса двух устройств. Улучшение внешнего вида само по себе их не устраняет. Cloudflare и Obsidian — собственная часть продукта, выходящая за рамки описанного локального плеера-ориентира.

## Рекомендуемая последовательность

1. Модель многотрековой книги, миграция данных, импорт и главы.
2. Надёжное воспроизведение: очередь, фон, позиция, история возврата, закладки, сон.
3. Удобство: библиотека, обложки, точные настройки, виджет и Android Auto.
4. Передача файлов, позиций и заметок между Android, Windows и Obsidian.
5. После измерений — обработка звука и Cast. Автоматическое создание обложек и рекомендации не являются условием готовности основного плеера.

Уровень готовности следует подтверждать сценариями из ТЗ. Термин «полный аналог Smart AudioBook Player» допустим только после отдельной проверки установленной актуальной версии по согласованной матрице функций.
