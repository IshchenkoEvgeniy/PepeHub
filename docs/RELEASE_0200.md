# PepeHub 0.20.0 — локальные Windows и Android сборки

14 октября 2026. Версия `0.20.0+50`, собрана из текущей рабочей копии по запросу пользователя.

## Что включено

- Раздел «Видео»: локальные файлы, папки курсов, прямые HTTP(S)-ссылки, продолжение позиции и скорости.
- Подробная статистика видео: реальное время, новый материал/повторы, покрытие, сессии, календарь, цели, серии, прогресс курса и отдельные отметки завершения/понимания.
- Полный экран, вписывание/обрезка/растяжение, поворот, точный переход, горячие клавиши и возврат до перемотки.
- A–B с количеством проходов и паузами; закладки и заметки к времени/диапазону с поиском, редактированием и отменой удаления.
- Накопленные изменения читалки и рекомендаций из рабочей копии на момент создания этих пакетов; они могут сохраняться отдельными коммитами.

## Пакеты

| Платформа | Файл в `dist/` | Размер |
| --- | --- | ---: |
| Windows x64 | `PepeHub-0.20.0-windows-x64.zip` | 45 008 141 байт |
| Android ARM64 | `PepeHub-0.20.0-android-arm64-test.apk` | 47 625 576 байт |

Windows: распакуйте **весь** архив и запустите `pepehub.exe`. DLL и каталог `data` должны оставаться рядом. В ZIP есть `START_HERE.md`. EXE содержит версию `0.20.0+50`; проверена загрузка всех 14 DLL из подготовленной папки. Упаковка использует текущий CMake install manifest и EXE: старый audio-only plugin, старый debug `native_assets.json` с абсолютными путями и неиспользуемая `zlib.dll` с зависимостью от debug CRT исключены. Рабочий `NativeAssetsManifest.json` с именами DLL сохранён; PDFium и SQLite включены.

Android: APK устанавливается поверх прежней версии с сохранением данных приложения. Проверены application ID `app.pepehub.pepehub`, версия `0.20.0`, versionCode `2050`, min SDK 24 / target SDK 36, только ABI `arm64-v8a`, отсутствие debug-флага и прежний сертификат подписи. Проверены `zipalign -c -P 16 4`, ELF LOAD alignment всех семи `.so` (не менее 16 KiB), медиаресурсы, шрифты и лицензии. Используется прежний проектный тестовый ключ.

Не очищайте данные приложения при обновлении. Данные видео пока хранятся только в локальной SQLite; переносимый видеожурнал, восстановление и экспорт остаются в плане. Windows и Android используют ту же схему SQLite версии 3.

## Проверки и ограничения

- Полный Flutter-прогон: 310 тестов прошли, 9 условных проверок пропущены. `flutter analyze --no-pub` — без замечаний.
- Серверные/интеграционные проверки: 48 тестов проходят; TypeScript typecheck — без замечаний.
- После Windows-сборки отдельно прошли 7 проверок видео/PDF с DLL из собранного пакета, включая короткий A–B, HTTP-видео, сохранение после seek и PDF на 1500 страниц.
- Windows release build и полный Android Gradle release build завершились успешно, включая новое нативное управление окном и системными панелями.
- Реальная Flutter-видеоповерхность/GPU, мониторы Windows и физический Android (SAF, lifecycle, клавиатура, поворот) требуют аппаратной приёмки. Декодер Windows соответствует закреплённому upstream media_kit и датирован 24.09.2023; обновление нативных бинарных зависимостей остаётся отдельной задачей перед публичным выпуском.
- Субтитры, расшифровка, PiP, аудио/study-режимы видео, постоянные агрегаты большой истории и внешние видеожурналы ещё не реализованы. [Текущий план](VIDEO_IMPLEMENTATION_PLAN.md).

Логи локальной сборки и проверок находятся в игнорируемом `build/video-release-*.log`.
