# Локальные кнопки сборки Windows и Android

Из корня проекта открывайте `.local/claude-check.cmd` для Windows или `.local/claude-android.cmd` для Android. Перед Windows-сборкой закройте приложение, запущенное из папки сборки. Два сборщика запускаются последовательно: они используют общие генерируемые файлы Flutter, поэтому второй одновременный запуск завершится с понятным сообщением.

Оба файла вызывают общий `scripts/run-local-build.ps1` под Windows PowerShell 5.1. Он проверяет локальные инструменты и шрифты/ресурсы из `pubspec.yaml`, выполняет `flutter pub get`, анализ и полный набор тестов приложения. При ошибке следующие этапы не запускаются; вывод виден в окне и записывается в лог. Предыдущий лог сохраняется рядом с суффиксом `.previous`.

Для Windows дополнительно выполняется `prepare-windows.ps1`: обновляются junction-ссылки плагинов и учитывается смена варианта аудио/видеодекодера. При первой ошибке Flutter, связанной с отсутствием права создания symlink, используются junction и повторная регистрация зависимостей. Обычные ошибки получения пакетов не игнорируются. Затем собирается release, проверяются наличие и версия EXE; после успеха открывается приложение. Результат: `apps/pepehub/build/windows/x64/runner/Release/pepehub.exe`. Самостоятельный ZIP эта кнопка не создаёт.

Для Android вызывается `build-android.ps1 -Architecture arm64` с включённым обновлением регистрации зависимостей. Сохраняются проверки подписи, версии, ABI, ZIP-выравнивания и медиаресурсов. После успеха Проводник выделяет APK в `dist/`. Используется существующий проектный тестовый ключ.

Логи кнопок: `.local/claude-check.log` и `.local/claude-android.log`. Итог `SUCCESS` появляется после проверок и сборки; `FAILED` содержит этап и причину. Окно остаётся открытым до нажатия клавиши. Старые `.local/claude-fonts.ps1`, `claude-quick.cmd` и `claude-open.cmd` не входят в этот процесс.

Общий сборщик доступен и напрямую из корня:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-local-build.ps1 -Target Windows
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-local-build.ps1 -Target Android
```

Добавьте `-NoOpen`, чтобы не открывать приложение/Проводник после успеха, либо `-CheckOnly`, чтобы проверить наличие локальных инструментов и ресурсов без получения зависимостей, тестов и сборки. Для автоматического вызова CMD можно задать `PEPEHUB_BUILD_NO_PAUSE=1`. Прямой сборщик возвращает ненулевой код при ошибке и по умолчанию пишет `.local/build-windows.log` или `.local/build-android.log`.

Содержимое `.local` по умолчанию исключено из Git; две CMD-кнопки добавлены в репозиторий точечно. Логи и остальные локальные настройки остаются игнорируемыми, общий обработчик находится в `scripts`. На другом компьютере требуется подготовить `.tools` и сохранить прежний ключ подписи для совместимых обновлений Android.

14 октября 2026: оба CMD и обработчик проверены под Windows PowerShell 5.1 в 21 сценарии с подставными командами. Проверены успешные запуски, stderr-предупреждения, остановка при ошибках зависимостей/подготовки/анализа/тестов/сборки, старые и отсутствующие результаты, повтор после symlink-ошибки, код возврата CMD, пути с пробелами и `&`, предыдущий лог, запрет одновременной сборки и безопасное исправление junction без удаления пакета. Проверки наличия инструментов и ресурсов также прошли в настоящем проекте. Реальные сборки после обновления кнопок не запускались.
