# Проверка читалки по форматам — 0.22.1+63

25 октября 2026 года. Проверены исходники выпуска `406493f` и добавлены тесты. Код приложения, версия, зависимости и пользовательская библиотека в рамках этой проверки не менялись. Новая сборка не выпускалась.

## Результат

**141 профильная Flutter-проверка прошла, без пропусков**, включая настоящий Windows PDFium из собранного приложения. Дополнительно **66 Android JVM/Robolectric-проверок доступа к книгам прошли** на API 26, 28 и 35: ошибок и пропусков нет. Анализ `lib/reader` и изменённых тестов — без замечаний.

Это не означает отсутствия дефектов: две новые проверки намеренно воспроизводят и фиксируют существующие проблемы. Они описаны ниже и **не исправлены**. После исправлений эти проверки нужно изменить так, чтобы они требовали сохранения изображений и отсутствия ошибки оформления PDF.

## Матрица форматов

Для каждого текстового расширения создавался отдельный настоящий файл, выполнялся импорт через `AssetStore.importBook`, затем книга открывалась обычным `ReaderPage` с загрузкой из файла и разбором в isolate. Готовый `ReaderDocument` в матрицу не подставлялся. Каждый сценарий выполнен при ширине **390 и 1280**, высоте 844; загружены реальные шрифты вместо тестовых квадратных глифов.

Общий сценарий: повторный импорт без дубликата → открытие → следующая страница → поиск уникальной фразы → переход и возврат → выделение текста с сохранением синей цитаты → именованная закладка → смена темы и режима → закрытие и повторное открытие. Проверены точная позиция, сохранённое оформление, цитата, закладка и неизменность исходника.

Для PDF проверен растровый лимит, а также готовность просмотрщика на документе **1500 страниц** до полной индексации. Это функциональная проверка, а не измерение скорости на реальном телефоне.

## Подтверждённые проблемы

### R-01 — Medium: импорт HTML/Markdown не переносит соседние изображения

- **Статус:** подтверждено воспроизведением для HTML и MD.
- **Место:** `apps/pepehub/lib/media/asset_store.dart`, `importBook` / `_importFile` (строки 203 и 272–277); `apps/pepehub/lib/reader/text_book.dart`, `loadTextBook` (строки 18–56).
- **Доказательство:** исходный `story.html` или `story.md` рядом с `map.png` даёт одну иллюстрацию. После `importBook` та же книга из `asset.path` даёт ноль иллюстраций, хотя текст сохранён. Это проверяет тест `characterization: imported HTML and Markdown lose adjacent images` в `reader_format_matrix_test.dart`.
- **Причина:** импорт копирует один выбранный файл в управляемую папку. Загрузчик ищет относительные изображения рядом с текущим файлом; после копирования это уже другая папка. Соседние файлы не импортируются.
- **Последствия:** пропадает часть содержания иллюстрированных HTML/Markdown-документов, импортированных обычной командой. Это не только ограничение Android SAF: воспроизведение выполнено на обычной файловой системе Windows.
- **Рекомендация:** явно определить импорт связанных ресурсов: сохранять проверенные локальные изображения в изолированную папку книги с ограничениями размера/количества и запретом выхода через пути/ссылки. Если отдельному Android-документу не предоставлен доступ к соседям, показать понятное ограничение. Встроенные data-изображения и архивные ресурсы EPUB/DOCX — другие пути обработки.
- **Будущая проверка:** заменить ожидание пустого списка в тесте на сохранение PNG и его привязки; проверить повторное открытие без исходной папки, отказ в доступе и запрет внешних URL/выхода из папки.

### R-02 — Medium: режим «Без пустых мест» попадает в несовместимый список настроек PDF

- **Статус:** подтверждено нативным widget-тестом с настоящим PDFium.
- **Место:** `apps/pepehub/lib/reader/pdf_reader_page.dart`, `_initial` (строки 114–119), `_appearance` (строки 591–603), возврат из `_openTextMode` (строки 858–866).
- **Доказательство:** сохранить `reader:appearance = {"mode":"compact"}`, открыть PDF и выбрать «Оформление». `DropdownButtonFormField(initialValue: value.mode)` получает `compact`, а его элементы содержат только `pages` и `scroll`. Flutter выдаёт `AssertionError`, содержащий `compact`.
- **Причина:** настройки общие для текстовой и PDF-читалки. При восстановлении PDF нормализует только `seamless`, оставляя `compact` без преобразования.
- **Последствия:** переход от текстовой книги с режимом «Без пустых мест» к оформлению PDF нарушает построение панели в проверяемом режиме Flutter. Точное поведение опубликованного release APK отдельно не проверялось: нельзя утверждать, что он обязательно завершится аварийно, поскольку диагностические assertions в release отключены.
- **Рекомендация:** нормализовать режим для PDF в обоих местах восстановления; в его список должны попадать только `pages` и `scroll`. Сохранить пользовательский текстовый режим при изменении только темы PDF.
- **Будущая проверка:** изменить тест `characterization: compact text preferences break the PDF appearance dropdown` так, чтобы он требовал успешного открытия настроек и корректного выбранного значения; добавить возврат из текстового режима PDF с `compact` и `seamless`.

## Ограничения и следующий шаг

- Подключённого телефона нет (`adb devices` пуст). Размер окна 390 — проверка компоновки, а не аппаратная проверка Android. Нужны реальные жесты выделения, экранная клавиатура, поворот/фон/возврат и SAF разных производителей.
- Использованы синтетические документы и временные библиотеки. Произвольные книги из личной коллекции не проверялись; пользовательские файлы не открывались и не менялись.
- Для PDF-сканов поиск по содержимому, цитата из текста и reflow требуют текстового слоя; OCR отсутствует. Позиция по страницам и заметки к странице — отдельные возможности. Новый нативный тест сканов/защищённых паролем PDF в этот прогон не добавлялся.
- В оригинальном PDF нет отдельного списка именованных закладок текстовой читалки: доступны оглавление/страницы, история переходов и заметки к страницам. Это различие функциональности, а не падение.
- Не проверены максимальные 20 000 страниц PDF, предельные размеры книг, полная CSS-вёрстка EPUB и все варианты Word/RTF. Профилирование памяти/скорости на телефоне не выполнялось.
- MOBI/AZW, DjVu, старый DOC, комикс-архивы и DRM не поддерживаются и не включались в успешную матрицу.

Сначала устранить R-02 локальным преобразованием режима PDF, затем определить и реализовать перенос локальных ресурсов R-01. После этого повторить матрицу и аппаратную приёмку Android. Для исправлений и публикации новой версии в этой проверке действий не выполнялось.
