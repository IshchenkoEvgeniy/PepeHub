# Обновления приложения через интернет

Сборка **0.25.0+72**, 28 октября 2026. **Настройки → Обновление приложения → Проверить обновления**. Отдельный публичный репозиторий `IshchenkoEvgeniy/PepeHub-Releases` содержит только готовые Windows ZIP, Android APK и подписанный `update.json`. Исходники PepeHub и ключи в него не отправляются. Первая сборка с механизмом обновления — `0.21.0+52`.

## Для пользователя

Первую сборку с этим механизмом нужно установить вручную один раз. В прежних приложениях ещё нет кода проверки обновлений.

- **Windows:** распаковать весь ZIP и запустить `pepehub.exe`. Следующие версии: «Скачать обновление» → «Обновить и перезапустить». Приложение сохраняет позицию плеера, закрывается, отдельный помощник заменяет файлы и снова запускает PepeHub. Запускать нужно из доступной для записи папки. Удалять прежнюю версию и переносить DLL вручную не требуется.
- **Android:** установить APK поверх существующего PepeHub. Следующие версии: скачать внутри приложения и нажать «Установить обновление». Если разрешение отсутствует, откроются настройки установки из PepeHub. После включения разрешения вернуться назад: установка продолжится автоматически. Отказ не запускает установщик. [Разрешение установки пакетов](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls()). Приложение не удаляется, его локальные данные сохраняются.
- Если установщик Android не появляется, использовать **«Скачать APK через браузер»**, открыть APK в загрузках браузера и установить поверх приложения. Ссылка также доступна в «Источнике обновлений». Для старых сборок 52–55, включая ошибку подписи в 0.21.2/0.21.3 на затронутых версиях Android, нужен однократный ручной переход на [APK 0.21.8](https://github.com/IshchenkoEvgeniy/PepeHub-Releases/releases/download/v0.21.8-60/PepeHub-android-arm64.apk).
- Приложение автоматически проверяет новую версию при открытии/возвращении на экран, не чаще одного раза в 12 часов. Проверку можно выключить; ручная кнопка остаётся. Загрузка и установка начинаются по отдельному нажатию, без внезапного закрытия во время чтения.
- Загрузка показывает размер и прогресс; после отмены/обрыва остаётся частичный файл. При повторе используется HTTP Range. Если сервер не поддерживает докачку, загрузка безопасно начинается заново.
- Обновления доступны без регистрации. Они скачиваются непосредственно из репозитория сборок GitHub.

Книги, заметки, статистика и системное хранилище токенов не входят в пакет приложения и не удаляются обновлением. На Windows меняются только файлы из проверенного пакета; неизвестные файлы рядом с EXE сохраняются. Устаревшие файлы удаляются только если перечислены в квитанции предыдущего обновления.

## Защита и восстановление

Манифест подписан Ed25519; открытый ключ встроен в `lib/updates/update_trust.dart`. Подписываются точные байты JSON: приложение сначала проверяет подпись, затем читает платформу, версию, даты, URL, размер и SHA-256. Иное приложение/канал, истёкший манифест, HTTP-адрес, неверный номер APK и откат ниже уже увиденной сборки отклоняются. GitHub перенаправляет публичные файлы на HTTPS-хранилище; клиент допускает до пяти перенаправлений, не передавая ключи GitHub или аккаунта. [GitHub release assets](https://docs.github.com/en/rest/releases/assets).

Перед установкой повторно проверяется весь скачанный файл. Android дополнительно сверяет `packageName`, номер/имя версии и сертификат с установленным приложением; саму установку выполняет системный установщик. Подпись прежних распространяемых APK сохранена. Автоматического бесконтрольного удаления приложения или обхода системного подтверждения нет.

Windows ZIP распаковывается в отдельном isolate в новый каталог. Запрещены переходы за корень, ссылки, имена устройств Windows, дополнительные потоки NTFS, дублирующиеся имена и неизвестные корневые файлы. Ограничены размер, количество файлов и распакованный объём. SHA-256 каждого распакованного файла передаётся помощнику и проверяется ещё раз перед закрытием приложения.

Помощник `assets/updater/install-windows.ps1` выполняется скрыто под текущим пользователем. Он проверяет родительский процесс, права записи и ссылки в путях, ожидает закрытия приложения, копирует заменяемые/удаляемые файлы в резервную копию и применяет пакет. При обрабатываемой ошибке возвращает затронутые файлы и открывает прежний EXE. Повторная попытка отменяет ранее ожидающего помощника. Открытые другие экземпляры блокируют обновление; процессы пользователя принудительно не завершаются.

Докачка, подготовка и резервные копии лежат в системном временном каталоге `pepehub-updates`. Старые скачанные пакеты очищаются при следующей загрузке; транзакции с резервными копиями сохраняются до очистки системного кеша. Внутри `windows-*` находятся `transaction.json`, `before.json`, `backup/`, `status.json` и при ошибке `failure.txt`. Для ручного восстановления после закрытия всех окон:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<транзакция>\install.ps1" -ConfigPath "<транзакция>\transaction.json" -Rollback
```

Откат относится к файлам приложения. Уже выполненные миграции пользовательской базы он не откатывает. Аварийное выключение питания посреди замены набора файлов не является атомарной транзакцией Windows; сохранённая резервная копия позволяет восстановить пакет, пока системный кеш не очищен. Аппаратная установка на конкретном Android и поведение антивируса/прав доступа Windows требуют отдельной проверки.

## Выпуск следующей версии

Обычные `.local/claude-check.cmd` и `.local/claude-android.cmd` создают локальные сборки. Приложение увидит новый выпуск через интернет после публикации обоих пакетов и подписанного манифеста в GitHub. Изменение исходников или одной строки версии не публикует обновление.

1. Увеличить `version`/номер сборки в `apps/pepehub/pubspec.yaml`. Даже при неизменном имени версии число после `+` должно расти. ARM64 APK использует Flutter ABI-offset: базовая сборка `60` даёт Android `versionCode=2060`.
2. Последовательно запустить `.local/claude-check.cmd` и `.local/claude-android.cmd`. Они выполняют проверки и собирают обе платформы.
3. Подготовить заметки к выпуску и пакеты:

```powershell
.\scripts\publish-update.ps1 -NotesFile .\docs\RELEASE_0218.md
```

Без `-Publish` ничего не отправляется: ZIP, APK и манифест появятся в `dist/online/<версия>-<сборка>/`. Скрипт проверяет версию Windows EXE, Android versionCode/ABI/сертификат и размеры/хеши. Windows ZIP содержит EXE, DLL и `data/`; PDB, база пользователя, `.local`, исходники и приватные ключи не упаковываются.

4. После просмотра результата опубликовать:

```powershell
.\scripts\publish-update.ps1 -NotesFile .\docs\RELEASE_0218.md -Publish
```

Используется Git Credential Manager для существующего входа GitHub. Токен читается только в память, в приложение/файлы/журнал не записывается. Скрипт проверяет владельца и публичность отдельного репозитория, создаёт черновик, загружает оба пакета и `update.json` и лишь затем публикует выпуск. Клиенты продолжают видеть прежнюю версию, пока новая не загружена целиком. Опубликованные сборки не перезаписываются; повторять можно только незавершённый черновик. Манифест действует 180 дней, после чего нужен новый выпуск или обновлённый подписанный канал.

Приватный ключ обновлений находится в игнорируемом `.local/update-signing/private.pem`; на этой машине доступ ограничен текущим пользователем и SYSTEM. **Сохранить его отдельную защищённую резервную копию.** `scripts/update-key.ts` отказывается молча создавать новый ключ, когда приложение уже доверяет прежнему. Android keystore из `.tools/android-user` тоже нужно сохранять. Потеря этих ключей нарушает совместимость автоматических обновлений. Публичный репозиторий не должен содержать ни один из них.

## Проверки реализации

- `update_test.dart`: подпись/подмена/срок, версии и откат, ограничение автоопроса, HTTPS, докачка, повреждённая загрузка/кеш, Android-разрешение, подготовка и отмена Windows-помощника, структура ZIP.
- `update_page_test.dart`: телефон 360×800, масштаб текста 1.5, скачивание, установка после возврата из настроек и запасной переход в браузер.
- `UpdateChannelTest.kt`: 23 нативные проверки Robolectric на API 26, 28, 29 и 35: целевой intent установщика, MIME/URI/ClipData и право чтения, проверка подписанта/хеша, разрешение после `onResume` с/без activity-result, отказ, тайм-аут без позднего запуска, HTTPS-переход в браузер и закрытая область FileProvider в объединённом манифесте. Дополнены случаи парсера Android 9/10, отсутствия сертификатов и запрета обхода настоящего несовпадения; [подробности](ANDROID_UPDATE_CERTIFICATES.md). При запуске на Windows создание URI подменяется фабрикой: AndroidX FileProvider сравнивает Unix-пути и не работает с Windows-путями тестовой JVM. Это не аппаратная проверка системного установщика.
- `audio_mini_player_navigation_test.dart`: переход на экран обновлений из настоящих настроек, сохранение одной работающей аудиопанели на телефоне и ПК.
- `update-publisher.test.ts`: подпись точного манифеста, адреса неизменяемого выпуска и запрет публикации изменившихся файлов.
- `windows-updater.test.ts`: настоящий скрытый PowerShell 5.1 и отдельный тестовый EXE; ожидание его закрытия, замена, сохранение посторонней книги/БД, удаление только старых управляемых файлов, ручное восстановление, ошибка посреди копирования и блокировка небезопасного пути.
