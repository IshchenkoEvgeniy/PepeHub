# История файлов общих папок

18 октября 2026. Опубликован [выпуск 0.21.5+57](https://github.com/IshchenkoEvgeniy/PepeHub-Releases/releases/tag/v0.21.5-57) для Windows и Android ARM64. Проверены публичный манифест, докачка/подготовка Windows и полное скачивание APK с SHA-256; [сведения о пакетах](APP_UPDATES.md).

## Настройки

История **выключена по умолчанию**, включая ранее подключённые папки без нового поля настроек. Она включается отдельно на каждом устройстве: **Устройства и общие папки → карточка папки → История и очистка**. Настройка хранится локально и не передаётся другому устройству.

При выключенной истории успешная замена не оставляет прежнего медиафайла. Подтверждённое удаление выполняется без резервной версии; диалог прямо сообщает об этом. Выключение истории сохраняет уже созданные копии до явной очистки или последующего включения ограничений.

При включении предлагаются **30 дней и 500 МБ**. На экране доступны 7/30/90/365 дней и 100 МБ/500 МБ/1 ГБ/5 ГБ. Срок рассчитывается по времени создания версии в служебном имени, а не по дате изменения исходной книги. Самые ранние копии удаляются первыми, пока не соблюдены оба ограничения. Лимиты применяются после сохранения версии и при обслуживании не чаще раза в сутки; ручная кнопка применяет их сразу. Просмотр страницы не откладывает очередную очистку включённой истории.

«Очистить историю» показывает количество/объём и требует подтверждения. Удаляются только распознанные файлы версий. Текущие медиа, незавершённые передачи, посторонние файлы и каталоги сохраняются. Кнопка переноса позволяет повторить неудачную миграцию сразу.

## Файлы и перенос

Windows и Android используют `.pepehub/p2p/versions` внутри выбранной общей папки. Новые версии именуются `v1-<миллисекунды>-<uuid>-<имя>`. Служебная папка исключена из обмена и автоматической библиотеки.

Старые Android `.pepehub-version-<миллисекунды>-<8 hex>-<имя>` переносятся из корня и вложенных папок при первой проверке либо открытии страницы истории. При выключенной истории перенос сохраняет даже старые копии, превышающие ограничения. Прежние Windows версии с микросекундами распознаются на месте. Непохожие имена не считаются управляемой историей.

Миграция отмечается в локальных метаданных по корню папки. Повторные обмены не обходят дерево ради поиска старых копий. Неудачная автоматическая попытка повторяется не чаще раза в сутки. Перенос и очистка записываются в журнал с количеством файлов и освобождённым объёмом.

SAF использует `DocumentsContract.moveDocument`. Если провайдер не поддерживает перенос, копия остаётся на месте и отображается причина; её можно явно очистить. Включённое архивирование, которое провайдер не способен выполнить, отклоняет замену с сохранением исходника. Выключенный режим работает через переименование. Полной промежуточной копии медиа в приватных данных приложения нет.

## Замена и откат

Предыдущий файл временно переименовывается для отката. На Windows он находится в `staging`, на Android с включённой историей — в `transactions`: обе служебные папки исключены из очистки истории. Даже очистка из другого движка приложения во время замены не удаляет данные отката. Если финальная публикация не удалась, файл возвращается на место. Повторная проверка захваченного файла сохраняет изменение, сделанное между первоначальной проверкой и переименованием. Только после успешной замены отключённая история удаляет временную версию, включённая переносит её в `versions` и применяет ограничения. При отказе последнего переноса резервная копия сохраняется в служебной папке, а причина записывается в журнал.

При аварийном завершении или отказе провайдера может остаться временный файл восстановления. Очистка истории не удаляет неподтверждённые данные отката и незавершённые передачи. Атомарная защита от произвольного внешнего изменения точно в момент операции и поведение всех SAF-провайдеров не заявляются.
