# Чтение подписи APK — 18 октября 2026

Пользователь установленной версии **0.21.2** получил при обновлении до 0.21.3 сообщение о несовпадении подписей. Локальные APK 0.10.0, 0.18.2, 0.20.0 и опубликованные 0.21.0–0.21.3 проверены `apksigner`: один и тот же SHA-256 сертификата `efeaed93980f9275749f27ec3b663b2f477984375ad3014e44d07c7a0048a620`. Доступного через ADB телефона нет; пользователь ещё не проверял установку из браузера, версию Android не сообщил.

## Подтверждённый дефект

`UpdateChannel` на API 28+ запрашивал только `GET_SIGNING_CERTIFICATES`. В AOSP Android 9 и Android 10 метод `PackageManager.getPackageArchiveInfo` вызывает `collectCertificates` только при наличии `GET_SIGNATURES`. Отсутствие сертификатов APK превращалось в пустое множество и сообщалось как несовпадение с сертификатом установленного приложения.

Первичные источники: [Android 9, PackageManager.java](https://android.googlesource.com/platform/frameworks/base/+/android-9.0.0_r1/core/java/android/content/pm/PackageManager.java), [Android 10, PackageManager.java](https://android.googlesource.com/platform/frameworks/base/+/android-10.0.0_r1/core/java/android/content/pm/PackageManager.java). Прежние проверки Robolectric выполнялись на API 26/35 с заранее заполненными сертификатами и не воспроизводили ветку парсера API 28/29.

## Исправление

Запрашиваются оба флага на API 28+, `GET_SIGNATURES` на более ранних версиях. Современные сертификаты имеют приоритет; при их отсутствии используются сертификаты, полученные через устаревшее API. Отсутствие данных и несовпадение ключей диагностируются раздельно. Пустые сведения не дают разрешения на установку; настоящее несовпадение не обходится через старые метаданные. Проверки хеша APK, имени пакета и возрастающей версии сохраняются.

Обновление исправляет будущую проверку. Уже установленный 0.21.2/0.21.3 содержит прежний код: на затронутом Android для первого перехода нужен запуск APK из браузера поверх установленного приложения. Ключ не меняется, удалять приложение не требуется.
