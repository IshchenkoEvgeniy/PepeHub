# Удаление книги и доступ к Android SAF

18 октября 2026. Исправление прав опубликовано в 0.21.6+58, обработка отсутствующих файлов — в [0.21.7+59](https://github.com/IshchenkoEvgeniy/PepeHub-Releases/releases/tag/v0.21.7-59) для Windows и Android ARM64. Проверены публичный манифест, полное скачивание APK и докачка/подготовка Windows; [сведения о пакетах](APP_UPDATES.md).

## Причина сообщения на скриншоте

Старая проверка в `AudioFolderChannel.deleteBookFile` для каждого разрешения на папку вызывала `DocumentsContract.isChildDocument(ContentResolver, Uri, Uri)`. Этот публичный overload добавлен в API 29. На API 26 проверка воспроизвела `NoSuchMethodError`, который `runCatching` превращал в false и сообщение «Нет права удаления». Отдельное разрешение на документ тоже отбрасывалось, поскольку не являлось разрешением на дерево. Сообщение само по себе не доказывало, что пользователь не выдал запись.

Первичные источники: [версия API метода](https://developer.android.com/reference/android/provider/DocumentsContract#isChildDocument(android.content.ContentResolver,%20android.net.Uri,%20android.net.Uri)), [tree-scoped URI](https://developer.android.com/reference/android/provider/DocumentsContract#buildDocumentUriUsingTree(android.net.Uri,%20java.lang.String)), [DocumentsProvider.enforceTree и callUnchecked](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/provider/DocumentsProvider.java).

## Поведение исправления

`BookFileAccess` принимает сохранённое разрешение на сам документ либо дерево с чтением и записью. При совпадении дерева URI используется непосредственно; для нового разрешения на родительскую папку документ проверяется запросом, привязанным к этому разрешению. Сам DocumentsProvider проверяет принадлежность документа дереву при query/open/delete. Строковые префиксы ID и вызов API 29 не используются. Корень и вложенные каталоги не удаляются, SHA-256 проверяется перед каждым удалением, учитывается FLAG_SUPPORTS_DELETE.

При реальном отсутствии записи возвращается `book_write_permission` с корнем папки. Экран библиотеки предлагает выбрать ту же папку. Системный ACTION_OPEN_DOCUMENT_TREE запрашивает read/write/persistable/prefix и показывает её в EXTRA_INITIAL_URI. Отмена возвращает false; иная папка или только чтение не считаются успехом. Получение разрешения не сканирует библиотеку и не удаляет файл самостоятельно.

После выдачи доступа библиотека повторяет все предварительные проверки всех копий, затем удаляет только неизменившиеся файлы. Уже подтверждённое удаление продолжается; при отмене разрешения оно останавливается. Повторный отказ по тому же корню не вызывает бесконечный цикл системных окон. Другие действия и восстановление истории этим механизмом не запускаются.

У провайдеров без поддержки удаления предлагаются файловый менеджер либо скрытие карточки. PlatformException и StateError в библиотеке отображаются через пользовательское сообщение.

## Уже отсутствующий файл — 0.21.7

Следующий скриншот показал `Failed to determine ... Missing file`: ExternalStorageProvider может выбросить IllegalArgumentException с FileNotFoundException при проверке дерева для уже удалённого документа. Первое исправление прав не учитывало этот сценарий. Точный случай добавлен в тест: на API 26/28/35 он падал до изменения (`book-missing-before.log`).

`BookFileAccess.confirmedAbsent` проверяет доступный корень и полный список его документов без чтения или хеширования содержимого. Только подтверждённое отсутствие позволяет завершить очистку карточки и кеша. Отсутствующему файлу не нужно право записи, если дерево можно прочитать. Ошибка чтения списка, null cursor, EXTRA_LOADING/EXTRA_ERROR, исчезновение корня или ограничения глубины/количества не считаются отсутствием; карточка сохраняется с понятным сообщением. Проверка запускается при ошибке доступа к документу или отсутствии записи, а не во время обычной синхронизации.

Дополнительно проверены исчезновение между preflight/commit и временный FileNotFound при наличии документа в списке. В последнем случае удаление не выполняется. Прежняя проверка SHA-256 и запрет удаления каталогов сохранены.

Нативный прогон: **57 passed** для доступа к книге (API 26/28/35), **28 passed** для истории, **23 passed** для обновлятора; всего **108**, ошибок нет (`book-missing-native-tests.log`). Dart-код удаления не менялся; полный предыдущий Flutter-прогон указан выше.

Повторный целевой Flutter-прогон: **10 passed** через настоящий экран библиотеки (`book-missing-flutter-tests.log`).
