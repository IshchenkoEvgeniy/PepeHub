# Повторная проверка библиотеки и статистики — 31 октября 2026

Разбор проверен по текущему рабочему коду и исполняемым сценариям. Основные
замечания подтвердились. Исходный замер «около двух секунд» и прогноз для
телефона нельзя переносить на другие машины без одинакового стенда.

| № | Результат проверки и изменение |
| --- | --- |
| 1 | `shelfIndex` действительно возвращал компактные данные, но заново разбирал полные индексы внутри SQLite. Схема 5 создаёт `reading_shelf_v1` один раз и обновляет только затронутую книгу при записи. Полка и проверка необходимости индексации читают эту проекцию. Старые позиции по абзацам разрешаются при изменении позиции или индекса; современные `textOffset` обновляют только число без разбора полного индекса. |
| 2 | Убрана общая `coverRevision`, пересоздававшая все видимые обложки при обычном обновлении полки. Ключ теперь зависит от ID книги, пути её обложки и признака скрытия. Отсутствие обложки запоминается на сутки; повторное подключение/сканирование папки сбрасывает отрицательный кеш. Недоступный исходный файл и ошибка Android-канала не записываются как подтверждённое отсутствие обложки. |
| 3 | Выбран минимальный вариант без смены формата пользовательского архива: небольшие случайные ревизии каталога, обновляемые триггерами. Повторный `entries` не читает большой JSON. `mutate` сравнивает результат с уже загруженным исходным значением, без второго чтения из SQLite. Случайный токен исключает совпадение ревизий после отката транзакции. |
| 4 | Поиск архива объединяет ввод за 200 мс; слова разбираются один раз на запрос, собирается только выбранный вариант поискового текста. Счётчики статусов файловых полок вычисляются одним проходом и кешируются. Перенос старого PDF-режима выполняется один раз за жизнь страницы. |
| 5 | Расчёты чтения вынесены из `build` в постоянный рабочий изолят. Даты отрезков разбираются один раз при загрузке; смена периода передаёт только условия. На экран возвращаются готовые итоги, серии и строки с длительностью, без массивов отрезков. Переключение месяца, раскрытие списка и изменение цели используют готовые данные. |
| 6 | Названия в статистике чтения и метаданные `bookInfo` берутся из компактной проекции. Полные `paragraphStarts` не загружаются ради названия или обложки. Предупреждения журналов читаются одним пакетным запросом вместо запроса для каждой книги. |
| 7 | Хаб читает компактные сессии без `events`/`ranges`; расчёт выполняется в изоляте. Готовые дневные данные переиспользуются календарём. Заголовки книг запрашиваются один раз и передаются в `BookCalendarData`. Серия внешних уведомлений объединяется в текущую загрузку и максимум один последующий проход. Кеш архива сверяется по малой ревизии. |
| 8 | Управление историей получает страницы по 100 записей. Полные payload читаются только для текущей страницы. Для списка не загружаются все аудиотреки: они читаются при открытии редактора события. Заголовки автоматических сессий сохраняются отдельно от JSON в вычисляемых колонках с индексом времени. Сортировка аудиособытий использует существующий индекс времени. |
| 9 | Сырые события остаются в исходной записи для экспорта, восстановления и синхронизации. Статистические проекции исключают `events` и `ranges`; полный JSON автоматической сессии загружается при открытии её редактора. Редактирование списка не теряет исходные события. |

## Сохранность данных

Миграция схемы 4 → 5 создаёт только производные таблицы и триггеры.
Исходные карточки, статусы, цитаты, история, обложки, индексы и позиции не
переписываются. Штатное открытие перед миграцией делает резервную копию
`VACUUM INTO` в `backups/before-v5-*.sqlite`. Начальное построение проекций
однократно разбирает старые данные на исполнителе базы; последующие экраны
получают готовые записи. Внешние записи, удаления и откаты обновляют
проекции в той же транзакции.

Карточки по-прежнему хранятся одним JSON-каталогом: изменение карточки
требует его перекодирования. Повторное чтение большого JSON и повторная
загрузка ради проверки кеша устранены. Переход на отдельную строку на
карточку здесь не выполнялся, чтобы сохранить формат архива и обмена.

Текстовый поиск по всей истории проверяет небольшие заголовки в изоляте,
затем получает одну страницу payload. Это сохраняет поиск по русскому
тексту и локальным датам, включая записи за пределами первой страницы.
При пустом поиске SQL ограничивает заголовки размером нужной страницы;
самый поздний переход через много страниц требует более длинного префикса
заголовков. CSV, счётчики и выделение относятся к показанным записям.

Общий прогон 21 тестового файла: **93 теста прошли**. После уточнения
обработки посторонних JSON-значений повторно прошли 18 проверок миграции,

Новые сценарии в `test/library_statistics_performance_test.dart` проверяют:

- 1000 индексов, **127 041 000 байт** исходного JSON → **104 891 байт**
  данных полки. В отдельном локальном прогоне два чтения полки заняли
  **34–44 мс**; запросы не обращались к исходным `reading-index:*`.
- Переход со схемы 4, резервную копию, точное сохранение исходных JSON,
  старых позиций абзацев и обложек.
- Двадцать чтений каталога без повторного чтения его JSON, откат транзакции
  и внешнюю замену данных.
- 100 000 отрезков чтения, группировку сессий, дробное попадание в период,
  совпадение времени, символов и дней с исходным алгоритмом.
- Страницы по 100 записей, отсутствие пересечений страниц, порядок от старых
  записей, поиск по русскому тексту и старой дате, сохранность сырых событий.
- Планы реальных запросов с `reading_statistics_time_v1` и
  `audio_event_time_v1`, отсутствие повторного запроса заголовков книг в хабе.
- Повторную проверку отсутствующей обложки и обнаружение новой после
  сканирования папки.
