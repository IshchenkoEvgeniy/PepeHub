# Необязательный ретранслятор PepeHub

Для уже сопряжённых ПК и телефона в разных сетях. Это отдельный сетевой сервис без базы/файлового хранилища, не облачная библиотека. Реализация: `services/relay/server.ts`; клиент — `peer_relay.dart`. Встроенного публичного сервера нет, в текущем сеансе ничего не развёрнуто.

## Запуск

Нужен сервер с Node.js 24+, доступным из интернета доменом и TLS-прокси, поддерживающим WebSocket. Скопировать исходники и lockfile; установить runtime-зависимости:

```powershell
npm.cmd ci --omit=dev
$env:RELAY_TOKEN = 'случайный-секрет-не-менее-24-символов'
$env:HOST = '127.0.0.1'
$env:PORT = '42593'
npm.cmd run relay
```

Настроить TLS-прокси: `wss://ваш-домен/v1/relay` → `http://127.0.0.1:42593/v1/relay`, сохраняя заголовки Upgrade/Connection и Authorization. Health-check: `GET /health`. Секрет передавать через окружение менеджера служб/секретов, не фиксировать в Git. На Linux используется `npm` без `.cmd`. Процесс должен запускаться менеджером служб; публичный HTTP/WS без TLS клиент отвергает, кроме localhost для тестов.

В PepeHub на обоих устройствах: **Настройки → Устройства и общие папки → Обмен через интернет**, одинаковые WSS-адрес и ключ доступа сервера. Сопряжение сначала выполняется через LAN. Ключ сервера хранится в защищённом хранилище и не заменяет отдельный секрет каждой пары. Пустой адрес отключает ретранслятор, пустое поле ключа сохраняет прежний ключ.

## Передача и ограничения

Клиент создаёт исходящее WebSocket-соединение для каждой пары. Номер комнаты выводится HMAC из секрета пары; сервер не получает сам секрет. Внутри туннеля действует тот же протокол TCP: новый challenge на запрос, AES-256-GCM, проверка получателя, прав папки и requestId. Даже знание ключа доступа сервера не даёт расшифровку библиотек. Сервер видит IP, идентификатор комнаты, время и объём трафика; он не выполняет аутентификацию аккаунта и не хранит файлы.

Прямое соединение имеет приоритет. При сетевой ошибке запрос повторяется через туннель; на минуту путь запоминается, чтобы не ждать подключения к недоступному LAN-адресу на каждом блоке. После минуты снова пробуется прямой адрес. Отсоединение закрывает активные потоки; файлы докачиваются штатным файловым протоколом после повторного соединения. При отзыве устройства туннель и ключ пары закрываются.

Сервер принимает только Bearer-ключ, браузерные Origin-запросы запрещены; по умолчанию 128 соединений и 16 на исходный IP, регистрация комнаты за 5 секунд, сообщение до 200 КБ, ограничение скорости и очереди отправки. Клиент держит до 8 потоков на пару; данные идут порциями до 64 КиБ с подтверждением и ограниченным ожиданием. Комната содержит максимум две стороны; когда сторона недоступна, сообщения не накапливаются. Пределы на IP относятся к адресу непосредственного соединения: за TLS-прокси клиенты обычно имеют один IP прокси. Для большого сервера пределы нужно настраивать с учётом доверенного прокси; текущие значения рассчитаны на личное использование.

Код проверен локальным настоящим Node-сервером и Flutter TCP-клиентами: большой шифрованный ответ, ошибочный ключ пары, отмена, разрыв и переподключение, fallback и отзыв доступа. Не проведён независимый аудит, публичная нагрузочная проверка или приёмка через реальную мобильную сеть.
