# PepeHub 0.19.0 — Windows и Android

13 октября 2026 года. Версия `0.19.0+49`; Windows x64 и Android ARM64. В выпуск включены обновлённый интерфейс и исправления технического аудита.

## Интерфейс

Обновлены навигация, книжная и аудиобиблиотека, рекомендации, заметки, статистика и настройки. Для интерфейса используются Onest, Oswald и Cormorant Garamond; текст книги сохраняет Lora. Шрифты и их лицензии включены в пакеты для работы без сети. Основной интерфейс использует тёмные палитры; тема текста выбирается в читалке.

## Исправления

- Повреждённая помеченная строка журнала Obsidian останавливает обмен и сохраняет исходные данные. Временно недоступный файл не становится командой удаления.
- Переносимые аудиожурналы сохраняют версии событий и удаления. Восстановление не выбирает устаревший интервал по большей длительности и не возвращает удалённую запись.
- Выбор конфликтующей версии проверяет актуальность обеих показанных сторон. Устаревшее окно не перезаписывает более новую правку.
- Заметки внешних аудиотреков передают номер трека и позицию без внутреннего `external:…` вместо SHA-256. Накопленные невалидные запросы исправляются; корректные повторные запросы сохраняют UUID и содержимое.
- Подключение папки не заменяет путь импортированной копии. При отключении папки импортированная книга остаётся доступной с теми же UUID, заметками и позицией чтения. Явный импорт ранее подключённой книги создаёт независимую копию.
- Чтение книги из Android SAF останавливается при превышении сохранённого размера; действуют пределы 64 МиБ для текста и 256 МиБ для PDF. Дескриптор закрывается, временные файлы удаляются при ошибке размера или SHA-256.
- Состояние журналов и заметок моста Obsidian хранится в двух чередующихся копиях с поколением и SHA-256. Оборванная запись восстанавливается из последней проверенной копии с сохранением UUID запросов. При повреждении обеих копий обмен останавливается без обнуления очереди. Неизменённое состояние повторно не записывается.
- Прототип `/v1` принимает проверенное необязательное смещение часового пояса для сессий. Новые сессии плеера используют канонический UTC и отдельное локальное смещение. Этот прототип по-прежнему скрыт в интерфейсе; рабочий обмен с Obsidian использует отдельный API Companion.
- Сбор заметок получает треки один раз на книгу и использует индекс предыдущих привязок вместо повторного поиска во всей истории. Регрессионная проверка на 20 заметках подтверждает один запрос треков.
- Windows CI проверяет все Flutter-тесты, серверные тесты и TypeScript перед сборкой. Версии Windows и Android теперь совпадают; CI не заменяет уже опубликованные пакеты.

## Совместимость и проверка

Полный локальный прогон: **224 Flutter-теста прошли, 5 пропущены**. **48 серверных и интеграционных тестов прошли**; полный Dart-анализ и проверка типов TypeScript — без замечаний. Проверены повтор запросов после оборванной записи состояния, сохранение офлайн-правок, восстановление аудиожурналов, чтение SAF и сохранение импортированных книг. Интеграционный тест двух Dart-клиентов проходит через настоящий локальный Worker HTTP и SQLite.

Обновление приложения не требует очистки данных. Аудиожурналы версии 1 читаются, новые дневные журналы имеют версию 2; предыдущие приложения не умеют читать новые журналы. Не откатывайте приложение после записи журналов версии 2.

Для исправлений на стороне Obsidian обновите исходники моста с помощью `scripts/install-obsidian-library-bridge.ps1`, пересоберите Habit Timer и перезапустите Obsidian. Скрипт также копирует новый `pepehub-durable-state.ts`. Прежний файл состояния сохраняется для первоначального переноса; после начала использования двух копий старый плагин будет читать устаревшее состояние, поэтому откат плагина не поддерживается. Изменение необязательного поля `/v1` требует обновления прототипного Worker, если он используется напрямую. Установленный плагин и внешние сервисы при подготовке этого выпуска автоматически не изменялись.

Физическое Android-устройство не подключено: SAF и мобильные сценарии проверены тестами с mock платформенного канала. Производительность очень больших библиотек и устойчивость файлового адаптера при аппаратном отключении питания требуют проверки на устройстве; числовые результаты профилирования не заявляются.
