# Схема базы 4: единая миграция

## Что изменилось

Раньше таблицы, индексы и триггеры функций создавались лениво при первом обращении: `PeerStore.initialize`, `AppSyncStore.initialize`, `AudioDailyStore.ensure`, `ReadingDailyTotals.ensure`, `VideoRepository.ensureIndexes`, `AudioJournal.ensureIndexes`, индексы заметок в `ReadingLibrary`, таблицы `CloudTransportState`. Номер схемы оставался 3, поэтому изменить такую таблицу без отдельной миграции было нельзя.

Теперь вся схема создаётся в `lib/data/database_schema.dart` (`createFeatureSchema`) и применяется шагом миграции `3 → 4` в `AppDatabase`. Новая база получает её в `onCreate`. Модули только читают и пишут данные.

- Шаг идемпотентен: у пользователя версии 3 часть таблиц уже есть, поэтому используется `IF NOT EXISTS`.
- Read-модели (`audio_daily_totals_v1`, `reading_span_*`) заполняются только при создании таблицы. Уже накопленные итоги не удваиваются.
- `library_source_revisions_v1` и триггеры источников отмечают изменения по книгам для кеша метаданных экспорта. Неизменённые значения и служебные записи обмена не инвалидируют кеш.
- Миграция выполняется в одной транзакции. При ошибке база остаётся версии 3. Перед переходом создаётся `backups/before-v4-<UUID>.sqlite`.
- Выражения, по которым построены индексы, вынесены в `SchemaSql`. Запрос должен повторять их дословно, иначе SQLite не использует индекс. Изменение такого выражения требует нового шага миграции.

## Индекс `records_audio_day`

Индекс версии 3 вычислял `json_extract` для **каждой** записи `records`. Одна повреждённая запись любого типа ломала его создание и все последующие вставки. Он заменён частичным индексом `records_audio_day_v2 (bookId, localDay) WHERE type='audio_event' AND json_valid(payload)`. Запросы экспорта журнала прослушивания и журнала Obsidian содержат то же условие.

## Видеоиндексы

Все пять видеоиндексов исключают записи с повреждённым JSON через `json_valid(payload)`. Миграция пересоздаёт прежние определения индексов версии 3 в той же транзакции. Запросы видео используют общие условия из `SchemaSql`, чтобы пропускать такие записи и сохранять использование частичных индексов. Исходные записи не удаляются.

## Журнал активности Obsidian

Поиск материализованных сессий чтения в `peer_app_projection` использует частичный индекс `peer_app_projection_target (target) WHERE materialized=1`, поэтому не требует полного просмотра проекций.

`ActivityStore.capture()` больше не читает все `audio_event` и `session` за всё время. Он выбирает события прослушивания только связанных книг через `records_audio_day_v2` и ручные сессии этих книг. `ActivityStore.foreign()` проверяет по первичному ключу только источники, на которые ссылается журнал, вместо полного списка записей и сессий чтения.

## Откат на 0.25.x

Версия 0.25.x откажется открывать базу версии 4 («База создана более новой версией»). Чтобы откатиться, восстановите `before-v4-*.sqlite`. Путь подготовки базы принимает восстановленную копию версии 1–4.
